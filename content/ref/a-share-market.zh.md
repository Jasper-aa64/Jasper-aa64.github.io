写因子、重建订单簿之前，先要知道交易所发来的数据各记了什么。前 4 节讲数据和规则，不展开交易所协议的每个字段，写到拿这些数据写程序够用为止；第 5 节讲怎么用逐笔把订单簿合成出来。

拿这些数据做的事在另外三页：算因子见[因子计算](/zh/ref/factor-computation/)；研究侧、回测、实盘怎么算得一样见[因子一致性](/zh/ref/factor-consistency/)；行情进来以后经过哪些线程见[交易系统架构](/zh/ref/trading-architecture/)。

## 1. 三类数据 {#data}

| 数据 | 记了什么 | 量级 |
|---|---|---|
| 快照 | 约每 3 秒一张：十档买卖价量、最新价、高开低收、累计成交笔数、量、金额，委买委卖总量；买一卖一前 50 笔挂单（委托队列） | 全市场一天两千多万条 |
| 逐笔委托 | 每一笔挂单（上海还有撤单） | 一天上亿条 |
| 逐笔成交 | 每一次撮合（深圳还有撤单） | 一天上亿条 |

**快照是结果，逐笔是过程**：快照只告诉你 3 秒后盘口变成什么样，谁主动成交、大单什么时候挂上又撤掉，只有逐笔看得到。Level-1 只有五档快照，没有逐笔。

## 2. 沪深两市的差别 {#sh-sz}

| | 深圳 | 上海 |
|---|---|---|
| 逐笔委托记什么 | 交易所收到的每一笔新委托，原始申报数量；类型分限价、市价、本方最优 | 进入订单簿的部分：立即全部成交的不发，部分成交的只发剩余量；类型分新增（A）、删除（D） |
| 撤单在哪 | 逐笔成交里，一条标着“撤销”的成交记录，价格写 0 | 逐笔委托里，一条“删除”（D）记录 |
| 主动方 | 没有标志，比较买卖双方委托序号，大的（后到的）是主动方 | 成交带内外盘标志：B 主动买、S 主动卖、N 未知 |
| 序号 | 频道内消息记录号，委托和成交共用 | 通道内业务序号，委托和成交共用 |

一句话记：**深圳的逐笔委托记“报了什么”，上海记“挂上了什么”**。所以同一个“大单委托”因子，两市要分开写。

撤单放在哪，也是从这个区别来的。上海的逐笔委托记的是订单簿上挂单的变化：一笔单挂上去，发一条“新增”（A）；被撤下来，发一条“删除”（D）。撤单自然就在逐笔委托里。深圳的逐笔委托只记新收到的委托，撤单不是新委托，放不进去；深圳的逐笔成交记的其实是委托的执行结果，结果有两种，成交了，或者撤销了。所以深圳的一笔撤单，是逐笔成交里的一条记录，只是它的类别标成“撤销”而不是“成交”（字段叫成交类别 `ExecType`，撤销写 `4`，成交写 `F`）。撤单没有成交价，这条记录的价格写 0；数量是撤掉的量；买卖双方的委托序号只有被撤那一边不是 0，用它查回原委托，才知道撤的是哪个价位。

**所以在深圳，用逐笔成交算任何东西，第一步都是先把撤销记录滤掉**：不滤的话，撤掉的量会被当成成交量，价格 0 会把均价拉低（[因子一致性第 2 节](/zh/ref/factor-consistency/#caliber)）。反过来，算撤单因子时，深圳要读逐笔成交，上海要读逐笔委托，只读一路就漏掉一个市场的撤单。

## 3. 序号、回查委托、主动方 {#seq}

第 2 节讲的是两市各发了哪些记录。真拿这些记录写程序（重建盘口、算因子），马上会碰到三个问题：消息按什么顺序处理；一条成交或撤单，对应的是哪笔委托；一笔成交是买方主动还是卖方主动。**三个问题靠的都是记录里的编号**：序号定先后，也用来发现丢包；委托编号把成交和撤单连回原委托；比较两个委托编号的大小，定主动方。

下面用一段深圳的逐笔把这三件事走一遍。四条消息在同一个通道里，时间戳都是 09:30:00.120：

| 序号 | 哪一路 | 内容 |
|---|---|---|
| 1001 | 逐笔委托 | 买入 500 股，价格 10.00 |
| 1002 | 逐笔委托 | 卖出 300 股，价格 10.00 |
| 1003 | 逐笔成交 | 成交 300 股，价格 10.00，买方是 1001，卖方是 1002 |
| 1004 | 逐笔成交 | 撤销 200 股，价格 0，买方是 1001，卖方空着 |

这一节的四件事都在这张表里。

### 3.1 先后只认序号 {#seq-order}

四条消息的时间戳一样，光看时间分不出先后。但交易所是一条一条处理的：先收到 1001，挂上去；1002 来了，和它撮合，产生 1003；最后 1001 剩下的 200 股被撤，就是 1004。序号记的就是这个处理顺序。深圳的委托和成交共用一套序号（消息记录号 `ApplSeqNum`），上海也一样（业务序号 `BizIndex`）。**所以要把两路按序号排好、合成一条流，才是盘口真实的变化顺序。** 按时间戳排，同一毫秒里成交可能排到引发它的委托前面，重建盘口时就会去成交一笔还不存在的委托。

序号只在一个通道内连续。交易所把股票分到多个通道，各自编号，不同通道的 1001 没有先后关系，只能各排各的。

### 3.2 丢包和重复 {#gaps}

同一通道里，序号一个挨一个。收到 1001、1002、1004，就知道 1003 丢了。这时 1001 那笔买单实际已经成交了 300 股，你的盘口却还以为它挂着 500 股，后面的计算全会偏。**所以丢了要补，补不到就把这段标成不可信，不能当没发生。** 反过来，断线重连后数据商常把最近一段重发一遍，已经处理过的序号直接丢掉，否则同一笔成交会被算两次。

### 3.3 回查委托：成交和撤单要找回原委托 {#lookup}

成交记录里只写了买卖双方是哪两笔委托，不写委托本身的信息。想知道这笔成交的买方原本报了多少股、一笔撤单撤的是哪个价位，都要拿编号去查委托。

深圳的成交里，买方、卖方委托序号（`BidApplSeqNum`、`OfferApplSeqNum`）就是那两笔委托自己的序号：表里 1003 的买方 1001、卖方 1002，直接对得上。撤单 1004 的价格是 0，而且只有一边有编号：卖方空着（写 0），买方是 1001。查回 1001，才知道撤的是 10.00 那一档的买单。

上海不一样，有两点。第一，成交里的买卖方订单号（`BuyOrderNo`、`SellOrderNo`）对的是委托的原始订单号（`OrderNo`），不是业务序号，查表时要用订单号做键。第二，上海的逐笔委托不发立即全部成交的单。上面那笔 300 股的卖单一来就全部成交了，上海只发出那条成交，逐笔委托里没有它，拿卖方订单号去查是查不到的。**所以上海的回查总会有一部分落空，这是正常的，不是丢包。**

### 3.4 主动方：谁去吃了谁 {#aggressor}

主动方是后到、主动去和已有挂单成交的那一方。表里的卖单 1002 来了，吃掉了已经挂着的买单 1001，所以 1003 是一笔主动卖。

上海的成交直接带内外盘标志：B 是主动买，S 是主动卖。深圳没有这个标志，要自己比：买卖双方的委托序号谁大，谁就是后到的，也就是主动方。1002 比 1001 大，所以卖方主动。

集合竞价是例外。9:25 那一次撮合，是把之前 10 分钟收到的单一起配对，没有谁先挂、谁去吃，成交没有主动方。上海标 N；深圳照样能比出一个更大的序号，但这个结果没有意义。**所以算主动买卖量时，集合竞价的成交要剔掉或单独处理**，否则深圳会凭空多出一批“主动”成交。

## 4. 集合竞价 {#auction}

A 股一天里有两种撮合方式。**连续竞价**是单子一到，就和对面挂着的单子比价，能成交就立刻成交，所以成交是一笔一笔陆续出来的。**集合竞价**是一段时间里只收单、不成交，到点后把收到的单子放在一起，算出一个让成交量最大的价格，所有能成交的单子都按这一个价格一次成交。开盘和收盘用集合竞价，中间用连续竞价：

| 时间 | 阶段 | 能做什么 | 行情里看到什么 |
|---|---|---|---|
| 9:15–9:20 | 开盘集合竞价 | 能下单，能撤单 | 只有委托，没有成交；快照上是“如果现在撮合”的参考价和量 |
| 9:20–9:25 | 开盘集合竞价 | 能下单，不能撤单 | 同上 |
| 9:25 | 开盘撮合 | — | 一批成交，价格相同、时间相同 |
| 9:25–9:30 | 等待 | 能下单，交易所先收着，9:30 才处理 | 没有新成交 |
| 9:30–11:30，13:00–14:57 | 连续竞价 | 正常交易 | 成交陆续出来 |
| 14:57–15:00 | 收盘集合竞价 | 能下单，不能撤单 | 只有委托 |
| 15:00 | 收盘撮合 | — | 一批成交，价格就是收盘价 |

9:20 以后不让撤单，是为了防止有人挂大单把参考价抬上去，快到点再撤掉，误导别人。集合竞价只收限价单，所以深圳逐笔委托里的市价单和本方最优委托，只会出现在 9:30–14:57 之间。

**这两次撮合出来的成交，和连续竞价的成交不是一回事**，写因子时有四处要单独处理：

- 没有主动方。所有单子是一起配对的，没有谁先挂、谁去吃（第 3.4 节），算主动买卖量必须把这些成交剔掉。
- 量很集中。9:25 一次就成交一大批，时间戳全是 9:25:00。如果把它并进 9:30 开始的第一根 1 分钟 bar，这根 bar 的成交量会远大于后面几根，按量算的因子在开盘这一根会失真。15:00 那批同理。
- 盘口是虚拟的。集合竞价期间快照上的买卖档是虚拟撮合的结果，不是真能成交的挂单，OBI、OFI 这类盘口因子要剔掉这段（[因子计算 1.1、1.2](/zh/ref/factor-computation/#obi)）。
- 委托要从 9:15 收起。9:15–9:25 挂的单子，没成交的部分会留到连续竞价里继续挂着，之后被撤或成交时要查回它，所以程序不能从 9:30 才开始收（[因子计算 1.5](/zh/ref/factor-computation/#cancel-ratio)）。

**所以集合竞价的成交要单独标出来**：剔掉、单独成一根 bar，还是并进第一根和最后一根，得和研究侧约定。研究侧拿分钟 bar 数据时，数据商往往已经按某种方式并好了，C++ 自己切 bar 要照着同一种来。

## 5. 订单簿：用逐笔合成每只股票的盘口 {#book}

1. **先分清几个名词：订单簿是全部，盘口是最前面几档，快照是每 3 秒拍的照片，逐笔是每一次变化**

   | 名词 | 是什么 | 谁有、多久一次 |
   |---|---|---|
   | **订单簿**（order book） | 交易所里所有还没成交的挂单，买卖两边各按价格排好，同一价格按时间排 | 完整的只在交易所的撮合系统里，每一笔都在变 |
   | **档** | 一个价位，比如 10.00 元那一档，就是所有挂在 10.00 的单加起来 | |
   | **盘口** | 订单簿里最靠近成交价的那几档：买一到买十、卖一到卖十，每档一个价格、一个总量 | 口语里常和订单簿混着说 |
   | **买一、卖一** | 买方出价最高的那档、卖方要价最低的那档，两者之间的差叫价差 | |
   | **快照** | 交易所隔一段时间拍的一张照片：十档盘口，加上最新价、累计成交量和成交额 | Level-2 约 3 秒一张 |
   | **逐笔委托** | 每来一笔新的挂单发一条：价格、数量、方向、委托号 | 每一笔都发 |
   | **逐笔成交** | 每成交一笔发一条：价格、数量、买卖双方的委托号；深圳的撤单也在这一路里 | 每一笔都发 |
   | **合成订单簿**（重建） | 自己拿逐笔，从开盘起一笔笔加、一笔笔减，在本地把订单簿复原出来 | 每来一条逐笔，就有一本最新的 |
   | **Level-1 / Level-2** | 行情的两个等级：Level-1 只有五档快照；Level-2 有十档快照，加上逐笔 | |

   - **逐笔是变化，订单簿是结果，快照是隔一会看一眼结果**：

     $$\underbrace{\text{订单簿}(t)}_{\text{全部挂单}} = \text{开盘时的订单簿} + \underbrace{\text{到 } t \text{ 为止的所有逐笔}}_{\text{每一次变化}}$$

     $$\underbrace{\text{快照}(t)}_{\text{每 3 秒一张}} = \underbrace{\text{订单簿}(t) \text{ 的前十档}}_{\text{盘口}} + \text{累计成交量、成交额}$$

   - **合成订单簿就是按第一个式子自己算**：算出来的前十档，在快照时刻应该和快照一样，这就是第 5 条的对拍。
   - **快照不是谁加工过的盘口**：它是交易所自己拍的，用快照算因子就是直接用交易所给的十档；合成订单簿才是自己用逐笔推出来的。

2. **合成订单簿：拿逐笔在本地把订单簿一笔笔维护出来**
   - **快照太粗**：约 3 秒一张，只有十档。因子想每来一条逐笔就更新，就得自己维护一本订单簿。
   - **在架构里的位置**：分片线程拿到一条逐笔，先更新这只股票的订单簿，再更新因子（[交易系统架构 1.1](/zh/ref/trading-architecture/#tick) 第 5 步，那里说的盘口就是这本订单簿）。所以订单簿和因子一样，只有一个线程写，不用加锁。
   - **规则一句话：委托加，成交和撤单减**：成交和撤单都按委托号找到原来那笔挂单，扣掉对应的量，扣到 0 就删掉。沪深每类消息的处理不一样，见 [5.1](#book-rules)。

   - **盘口不是单独的一步，是去读订单簿的前几档**：盘口类因子直接读订单簿里买一、卖一的下标，往外看几档。不会每条逐笔都把前十档拷出来另存一份，那是白做功。
   - **深度类、排队类因子读得更深**：比如前二十档的总量、买一那档排在前面的单有多少。快照给不了这些，只有自己的订单簿有。
   - **逐笔类因子不经过订单簿**：主动大单净流入看的是这一笔成交谁主动、多大，直接读这条逐笔，和订单簿长什么样无关。
   - **定时取前十档只在两处**：
      - **对拍**：每到交易所快照时刻取一次，和快照比（第 5 条）。
      - **给研究侧合成快照**：研究员的因子按快照写的，就每隔固定时间（比如 1 秒）从订单簿取一份前十档。比交易所的快照更密，时刻也能自己定。

4. **数据结构：价格档用数组，委托号用哈希表**
   ```cpp
   struct Order { int32_t px; int64_t qty; bool is_bid; };   // 一笔挂单：价位下标、剩余量、方向

   struct Book {
       int32_t lo;                                     // 跌停价，单位是最小价位（0.01 元）
       std::vector<int64_t> bid_qty, ask_qty;          // 每档总量，下标 = 价格 - 跌停价
       int32_t best_bid, best_ask;                     // 买一、卖一的下标
       std::unordered_map<uint64_t, Order> orders;     // 委托号 → 挂单

       void add(uint64_t id, int32_t price, int64_t qty, bool is_bid) {
           int32_t i = price - lo;
           orders[id] = {i, qty, is_bid};
           (is_bid ? bid_qty : ask_qty)[i] += qty;
       }
       void reduce(uint64_t id, int64_t qty) {         // 成交和撤单都走这里
           auto it = orders.find(id);
           if (it == orders.end()) return;             // 上海的主动方本来就不在盘口里
           Order& o = it->second;
           (o.is_bid ? bid_qty : ask_qty)[o.px] -= qty;
           if ((o.qty -= qty) == 0) orders.erase(it);
       }
   };
   ```
   - **价格档用数组，以最小价位为下标**：A 股有涨跌幅限制，一天里能出现的价位是有限的。10 元的主板股票涨跌 10%，价格只能在 9.00–11.00 之间，一共 201 档。`价格 − 跌停价` 就是下标，增删都是直接定位，不用查找。
   - **委托号用哈希表**：成交和撤单只带委托号，要先按号找到那笔挂单，才知道它在哪一档、还剩多少。热路径上用开放寻址的哈希表（比如 `absl::flat_hash_map`），元素连续放，比 `std::unordered_map` 的链表少几次缓存缺失。
   - **买一、卖一单独记一个下标**：买一被吃空了，从这个下标往下扫到下一个非空的档。档位稀疏时扫得慢，可以再加一个位图，每一位表示一档空不空，一条指令就能找到下一个非空档。
   - **为什么不用 `std::map`（红黑树）**：每次更新都要往下走好几层，每层一次缓存缺失，插入还要分配节点。价格范围本来就是固定的，数组直接定位更快。
   - **每档只存总量就够大多数因子用**：要算某笔单排在这一档的第几位，才需要再按时间存每档的委托队列。
   - **例外：新股上市头几天没有涨跌幅限制**：价格范围定不下来，数组要开大一些，或者随价格变化往外扩。

5. **怎么验：和交易所快照逐档比**
   - **错了没人告诉你**：盘口重建错了，程序照样跑，因子照样出数。能拿来核对的只有交易所的快照，所以重建和对拍要一起做。

> **合成的订单簿怎么验**
> - **每到一个快照时刻，拿重建出来的十档和快照逐档比**：比每档的价和量，再比累计成交量和成交额。
> - **先对齐时刻**：快照不带逐笔的序号，先把时间不晚于快照的逐笔处理完再比；对不上，在前后一小段里逐条往前推。
> - **集合竞价那段不比**：只挂单不撮合，买一可以高于卖一，从连续竞价开始比。
> - **对不上先查三处**：丢了逐笔（按序号查连续）；撤单那一路漏了（深圳在逐笔成交里，上海在逐笔委托里）；市价单、本方最优单的价格没按规则补。
> - **盘中对不上只停这一只股票**（[交易系统架构 4.3](/zh/ref/trading-architecture/#incidents)），原因盘后查。各种对不上分别说明什么，见 [5.2](#book-check) 和 [5.3](#book-diff)。

> **重建订单簿不撮合，撮合逻辑用在别处**
> - **撮合是交易所做的，逐笔成交就是撮合的结果**：重建只是照着消息加、减，不判断能不能成交。
> - **深圳盘口会暂时交叉，也不用自己撮**：一笔够得着对面的限价委托进来，它的成交消息稍后才到，这中间买一可能不低于卖一；等成交消息来了再扣量。上海的委托消息给的是撮合后剩下的量，没有这一步。
> - **回测里的撮合模拟器，是撮合逻辑用得最多的地方**：历史行情里没有自己的单，挂在哪一档、前面排着多少量、什么时候成交、成交多少、从发单到交易所的延迟，都要自己模拟。模拟得太乐观，回测收益就是虚的。
> - **集合竞价的参考价，按撮合规则算**：竞价阶段只收单不成交，参考价取成交量最大的那个价。快照里一般带着，自己算是为了推算多一笔单价格会怎么变。
> - **测试用的模拟交易所**：联调时用一个本地撮合引擎扮演交易所，接报单、回成交和回报，不用连真实柜台就能测下单、撤单、部分成交。
> - **因子回算用不到它**：因子只读行情，不下单。要模拟自己的单怎么成交，那是策略回测的事。

### 5.1 每类消息怎么改盘口 {#book-rules}

- **盘口里存什么**：每个价位一个总量，再按编号记每笔挂单的方向、价格、剩余量。成交和撤单都要按编号找到原来那笔挂单（[3.3](#lookup)）。
- **处理顺序**：两路合成一条流，严格按序号处理（[3.1](#seq-order)），丢了就补，补不到就把这段标成不可信（[3.2](#gaps)）。

1. **深圳**
   - **逐笔委托（限价）**：加一笔挂单，那个价位加上它的原始申报量。
   - **逐笔成交（`F`）**：买卖两边的委托都扣掉成交量，扣到 0 就从盘口删掉。两边都要扣，因为深圳的逐笔委托把主动方也发了，它已经被加进了盘口。
   - **撤单（逐笔成交里的 `4`）**：价格是 0，按不为 0 的那一边编号找到原委托，扣掉撤销量。
   - **市价单、本方最优单**：委托里的价格字段不一定是它真正挂上去的价格。本方最优按当时己方的最优价挂，市价单剩下的部分各有各的处理规则。字段怎么填，以数据商的文档为准，再拿真实数据核一遍。
   - **中间会交叉**：一笔能成交的限价单先加进盘口，紧跟着的几条成交才把它扣掉。这一串处理完，盘口就正常了，**不要在一串的中间取盘口**。

2. **上海**
   - **新增（`A`）**：加一笔挂单，量是进入订单簿的剩余量（[第 2 节](#sh-sz)）。
   - **删除（`D`）**：按订单号找到这笔挂单，删掉。
   - **成交**：只扣被动方。主动方要么立即全部成交，逐笔委托里根本没有它；要么只把剩余量用 `A` 发出来，成交掉的那部分本来就没进盘口。内外盘标志 `B` 扣卖方，`S` 扣买方。
   - **集合竞价的成交（`N`）**：两边都是竞价期间挂上去的，两边都扣。

3. **两市的差别归成一句**
   - **深圳的盘口先加后扣，上海的盘口只加剩下的**。深圳逐笔委托记“报了什么”，主动方也得先加再扣；上海记“挂上了什么”，主动方从来不在盘口里，成交只扣被动方。

### 5.2 和快照十档对拍 {#book-check}

1. **对什么**
   - **十档的价和量**：自己的盘口取买卖各前十档，和快照逐档比价格和总量。
   - **累计成交量、成交额、成交笔数**：把处理过的成交加起来，和快照里的累计值比。深圳先滤掉撤销记录（[第 2 节](#sh-sz)）。这几个数一旦差了，差额会一直留着，很好认。

2. **在哪个时刻比**
   - **难点**：快照只带时间戳，不带逐笔的序号，看不出它是在哪一条逐笔之后生成的。
   - **做法**：先把时间戳不晚于快照时间的逐笔处理完，再比。对不上时，在快照时间前后一小段里逐条往前推，只要其中有一个时刻十档全对上，就算对上。
   - **从连续竞价开始比**：集合竞价期间只挂单不撮合，买一可以高于卖一，快照上是虚拟撮合的结果（[第 4 节](#auction)），不能按连续竞价的办法比。

### 5.3 对不上说明什么 {#book-diff}

- **只在快照时刻附近差一点，过一会儿自己对上**：时间对齐的问题，盘口没错。
- **某一档一直多出一个固定的量**：漏扣了一次。最常见的是深圳的撤单在逐笔成交里没处理，或者回查委托落空，也可能是丢包（[3.2](#gaps)）。
- **买一高于卖一，而且一直不消失**：成交没扣对。深圳常见于只扣了被动方、没扣主动方；把价格为 0 的市价卖单直接挂进盘口，也会出现一个价格为 0 的卖一。
- **累计成交量对不上**：丢了成交，重复处理了断线重连后重发的数据（[3.2](#gaps)），或者深圳没滤撤单。
- **对拍不过的那段时间，基于盘口的因子都不能用**。和研究侧对因子之前，先看这段盘口有没有对上。
