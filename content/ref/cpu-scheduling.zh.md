一个核同一时刻只跑一个线程，可运行的线程却常常比核多。调度器每次要回答两件事：什么时候把当前线程换下来，换谁上。前一件是抢占，后一件是调度策略；不同策略的差别，在于它们在吞吐量、周转时间、响应时间之间怎么取舍。

## 1. 调度时机：什么时候把当前线程换下来 {#when}

### 1.1 非抢占与抢占：线程不想让时，也能被换下来 {#preemption}

**线程自己让出 CPU（阻塞、退出）时一定会换；抢占式调度还会在线程不想让的时候把它换下来，触发点是时钟中断和更高优先级的线程被唤醒。**

- **非抢占式**：只在线程阻塞（等 I/O、等锁）或退出时换下一个。一个死循环的线程会一直占着核，交互程序就卡住，所以通用系统都不用它。
- **抢占式**：时钟中断到来时，调度器检查当前线程的时间片用完没有；一个更高优先级的线程被唤醒时，也会检查要不要换。
- **Linux 里抢占不是当场切**：调度器先给当前线程打一个“需要重新调度”的标记，等从中断或系统调用返回用户态时才真正切换。内核代码执行到一半能不能被抢占，看内核的抢占模式，见 [#19 第 3 节](/zh/posts/scheduling-priority-inversion-kernel-tuning/)。
- **被换下来的线程还在运行队列里**：它的状态仍是 R（可运行），只是没在核上，见[进程和线程 3.1](/zh/ref/process-thread-fork/)。

### 1.2 三个指标：吞吐量、周转时间、响应时间 {#metrics}

**调度策略之间没有绝对的好坏，只有在三个指标之间怎么取舍：切换越少吞吐越高，先跑短的周转越短，时间片越短响应越快。**

- **吞吐量**：单位时间完成多少任务。每次切换都要保存、恢复寄存器，缓存还得重新热起来（[上下文切换](/zh/posts/low-latency-context-switch-page-table-tlb/)），切换越少，用来干活的时间越多。
- **周转时间**：一个任务从到达到完成的时间，批处理关心它。
- **响应时间**：从到达到第一次上 CPU 的时间，交互程序关心它。
- **三者互相拉扯**：时间片调短，响应快了，切换多了，吞吐就降；总是先跑短任务，平均周转最短，长任务却可能一直等。

## 2. 经典调度算法：同一组任务，换一种挑法 {#classic}

下面几节都用同一组任务：三个任务在 0 时刻同时到达，P1 要跑 24 个单位时间，P2、P3 各要 3 个，到达顺序是 P1、P2、P3。

| 算法 | 每次挑谁 | 抢占吗 | 这组任务的平均等待 | 主要问题 |
|---|---|---|---|---|
| FCFS | 最早到的 | 否 | 17 | 长任务挡住短任务 |
| SJF | 要跑得最短的 | 否 | 3 | 要预知长短；长任务饿死 |
| SRTF | 剩余时间最短的 | 是 | 3 | 同上，还要频繁比较 |
| 优先级 | 优先级最高的 | 可以是 | 看优先级怎么设 | 低优先级饿死 |
| RR（时间片 4） | 队头，跑一个时间片就排到队尾 | 是 | 约 5.67 | 时间片难定 |
| MLFQ | 最高一级队列的队头 | 是 | 接近 SJF | 参数多 |

### 2.1 FCFS（先来先服务）：长任务挡住后面所有短任务 {#fcfs}

**按到达顺序跑，实现只要一个队列；代价是一个长任务排在前面，后面的短任务全都要陪它等，这叫护航效应（convoy effect）。**

- **按 P1、P2、P3 的顺序跑**：P1 等 0，P2 等 24，P3 等 27，平均等待 $(0 + 24 + 27) / 3 = 17$。
- **同样三个任务，P1 排到最后**：等待是 0、3、6，平均 3。同一组任务，只是顺序不同，平均等待差了 5 倍多。

### 2.2 SJF 和 SRTF：先跑短的，平均等待最短，但要预知长短 {#sjf}

**SJF（短作业优先）每次挑要跑得最短的任务，可以证明它让平均等待时间最小；问题是任务要跑多久事先不知道，而且短任务源源不断时，长任务会一直等下去。**

- **这组任务按 SJF 是 P2、P3、P1**：平均等待 3，就是 2.1 里那个最好的顺序。
- **为什么最短**：任意一个排法里，如果一个长任务排在一个短任务前面，把两者对调，短任务少等的比长任务多等的多，总等待只减不增。一直对调下去，就是按长短排好的顺序。
- **SRTF（最短剩余时间优先）是它的抢占版**：新任务到达时，剩余时间比当前任务短，就抢占当前任务。
- **长短只能估计**：常用上一次的估计值和实际值做指数平均，$\tau_{n+1} = \alpha\, t_n + (1 - \alpha)\, \tau_n$，其中 $t_n$ 是第 $n$ 次实际跑的时长，$\tau_n$ 是对它的估计，$\alpha$ 在 0 和 1 之间，越大越看重最近一次。
- **长任务会饿死**：短任务一直来，长任务永远排不到前面。

### 2.3 优先级调度：高的先跑，低的可能饿死 {#priority}

**每个任务带一个优先级，每次挑最高的；SJF 就是“越短优先级越高”的特例。低优先级任务可能永远轮不到，办法是老化（aging）：等得越久，优先级提得越高。**

- **可以抢占，也可以不抢占**：抢占式里，高优先级任务一就绪就把低优先级的换下来。
- **饿死和老化**：低优先级任务在队列里每多等一段时间，就把它的优先级提一点，总有一天能排到前面。
- **和锁放在一起时还有优先级反转**：低优先级线程拿着锁，被中优先级线程抢走 CPU，等锁的高优先级线程跟着一起等，见 [#19 第 2 节](/zh/posts/scheduling-priority-inversion-kernel-tuning/)。

### 2.4 RR（时间片轮转）：轮流跑，响应最快，时间片难定 {#rr}

**就绪队列里的任务轮流跑，每次最多跑一个时间片，没跑完就排到队尾；每个任务很快就能第一次上 CPU，代价是切换多，时间片的长短决定它更像 FCFS 还是更像频繁切换。**

- **这组任务、时间片 4**：P1 跑 0–4，P2 跑 4–7，P3 跑 7–10，剩下的全是 P1，跑 10–30。等待时间是 P1 等 $10 - 4 = 6$，P2 等 4，P3 等 7，平均约 5.67；第一次上 CPU 的时间是 0、4、7。
- **和 FCFS 比**：平均等待从 17 降到约 5.67，P2、P3 不用再等 P1 跑完。
- **时间片太大，就退化成 FCFS**：每个任务都在一个时间片里跑完，轮转不起作用。
- **时间片太小，切换的开销占比就高**：每次切换都要保存、恢复寄存器，缓存和 TLB 还要重新热起来，真正干活的时间被切换吃掉。

### 2.5 多级队列和多级反馈队列（MLFQ）：不用预知长短，也能先跑短的 {#mlfq}

**MLFQ 设几级队列，越高的一级优先级越高、时间片越短；任务用完时间片就降一级，所以短任务和交互任务留在上面先跑，长任务沉到下面。它不用预知任务长短，就近似出了 SJF 的效果。**

1. **多级队列：按类型固定分队**
   - **每类任务一个队列**：比如前台交互任务一个队列，用 RR；后台批处理一个队列，用 FCFS。
   - **队列之间按固定优先级排**：前台队列有任务，后台的就不跑。任务进了哪个队列就一直在那里，不会移动。

2. **多级反馈队列：按实际表现在队列之间移动**
   - **新任务进最高一级**：先假设它是个短任务。
   - **用完这一级的时间片就降一级**：跑得久的任务一级级往下沉，下面的队列时间片更长，切换更少。
   - **在时间片用完之前就让出 CPU 的，留在原来那一级**：等 I/O 的交互任务因此一直待在上面，响应快。
   - **防钻空子：按在这一级累计用掉的时间降级**：只看“这次有没有用完时间片”的话，一个任务每次快用完时主动让出一下，就能永远留在最高级；改成累计，跑够了就降。
   - **每隔一段时间把所有任务提回最高级**：防止下面的任务饿死，也让行为变了的任务（从计算转成交互）有机会回到上面。

### 2.6 实时调度：EDF 和 RMS，按截止时间排 {#realtime}

**实时任务看的不是平均快慢，而是每次都在截止时间前跑完。EDF 每次挑截止时间最早的；RMS 给周期越短的任务越高的固定优先级。**

- **EDF（最早截止时间优先）**：优先级随截止时间动态变化。单核上，周期任务的截止时间等于周期时，只要总利用率 $U = \sum_i C_i / T_i \le 1$（$C_i$ 是每次要跑的时间，$T_i$ 是周期），EDF 就能让所有任务都按时跑完。
- **RMS（单调速率调度）**：优先级固定，按周期排，周期越短优先级越高。它保证按时的条件更紧：$n$ 个任务时总利用率不超过 $n\,(2^{1/n} - 1)$，任务很多时约 69%。
- **Linux 的 `SCHED_DEADLINE` 用的就是 EDF**（3.1）。

## 3. Linux 的做法 {#linux}

### 3.1 调度类：先比类，再在类里挑 {#classes}

**Linux 把线程分进几个调度类，每次按固定顺序问：stop → deadline → 实时 → 普通 → idle。前面的类里有可运行的线程，后面的类就轮不到。**

- **deadline 类（`SCHED_DEADLINE`）**：EDF，按“每个周期要跑多少、截止时间在哪”排。
- **实时类（`SCHED_FIFO`、`SCHED_RR`）**：优先级 1–99，严格按优先级抢占。`SCHED_FIFO` 抢到核就一直跑，直到阻塞或让出；`SCHED_RR` 在同一优先级之间按时间片轮转。
- **普通类（`SCHED_OTHER` 等）**：绝大多数线程在这里，按权重分 CPU 份额（3.2）。
- **设置方法、RT 限流、饿死内核线程这些坑**：见 [#19 第 1 节](/zh/posts/scheduling-priority-inversion-kernel-tuning/)。

### 3.2 普通类：CFS 按 vruntime 分份额，EEVDF 再加上虚拟截止时间 {#cfs-eevdf}

**CFS 让每个线程按权重拿到应得的 CPU 份额，每次挑“已经跑得最少”的那个；内核 6.6 起换成 EEVDF，在“还没拿够份额”的线程里挑虚拟截止时间最早的，申请短时间片的线程因此更早轮到。**

1. **CFS（完全公平调度器）：挑 vruntime 最小的**
   - **vruntime 是按权重折算的已运行时间**：线程每跑一段，vruntime 就加上“实际运行时间 × nice 0 的权重 ÷ 自己的权重”，权重越大涨得越慢。
   - **每次挑 vruntime 最小的线程**：可运行的线程放在一棵按 vruntime 排序的红黑树里，最左边的节点就是下一个（[红黑树](/zh/ref/skiplist-rbtree-bplustree/)）。
   - **nice 值决定权重**：nice 从 −20 到 19，每差 1 级权重约差 1.25 倍，两个线程 nice 差 1，CPU 份额大约差 10 个百分点。
   - **和经典算法的关系**：它相当于时间片无限小、按权重分配的 RR，追求的是份额公平，不管谁先谁后。

2. **EEVDF（最早合格虚拟截止时间优先）：在没拿够份额的线程里，挑截止时间最早的**
   - **lag：应得的减去实际拿到的**：lag 为正，说明这个线程还欠着 CPU 时间；为负，说明它多拿了。
   - **只在 lag ≥ 0 的线程里挑**：这些线程叫“合格的”（eligible），多拿了的先等一等。
   - **再挑虚拟截止时间最早的**：每个线程按自己申请的时间片算出一个虚拟截止时间，时间片越短，截止时间越早，越先跑。所以对延迟敏感、每次只跑一小会儿的线程，响应更快。
   - **截止时间更早的线程可以抢占当前线程**：线程还能用 `sched_setattr()` 申请自己的时间片长度。
   - **出处**：[内核文档 EEVDF Scheduler](https://docs.kernel.org/scheduler/sched-eevdf.html)。

### 3.3 每个核一个运行队列：负载均衡会把线程挪走 {#runqueue}

**每个核有自己的运行队列，调度器只在本核的队列里挑；核之间的负载靠定期的负载均衡来拉平，代价是线程被挪到别的核，缓存和 TLB 要重新热。**

- **每核一个队列，挑线程不用和别的核抢锁**：调度器只看本核的队列。
- **负载均衡定期把线程从忙的核挪到闲的核**：核空下来时，也会主动从别的核拉线程过来。
- **线程被唤醒时也要选一个核**：一般倾向放回它上次跑的核或附近的空闲核，那里的缓存可能还热。
- **挪核就要重新热缓存**：L1、L2 和 TLB 都是新的，这是低延迟线程要绑核的原因，见 [#1 第 1.1 节](/zh/posts/cpu-affinity-core-isolation-numa/)。

### 3.4 低延迟系统怎么用：让热线程不参与调度 {#low-latency}

**热线程最好的调度是不被调度：独占一个隔离的核、绑核、忙轮询不睡，调度器就没有理由换掉它；必须和别的线程共用核时，才用实时优先级。**

- **隔离加绑核**：`isolcpus` 让调度器不往这些核上放别的线程，再把热线程绑上去，没有别的线程和它抢（[#1 第 1 节](/zh/posts/cpu-affinity-core-isolation-numa/)）。
- **忙轮询不睡**：线程不阻塞，就不会经历“唤醒 → 排队 → 上核”这一串延迟。
- **共用核时用 `SCHED_FIFO`**：普通类只保证份额，热线程恰好在别人的时间片开头醒来，要等 ms 级；实时类一就绪就抢占。要注意 RT 限流和优先级反转，见 [#19 第 1.3 节和第 2 节](/zh/posts/scheduling-priority-inversion-kernel-tuning/)。
