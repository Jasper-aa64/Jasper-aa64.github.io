这页讲一个因子的内部：定义怎么落成状态，状态怎么随每条消息更新，代码怎么写。先是几个常用因子，再是批处理改成流式要重做的三件事，最后是拿到一个新定义时怎么动手。

因子外面的事在另外三页：数据各记了什么见 [A 股行情](/zh/ref/a-share-market/)；同一个因子在研究侧、回测、实盘三处怎么逐值对上见[因子一致性](/zh/ref/factor-consistency/)；谁把行情喂给因子、线程怎么分、订单簿怎么维护见[交易系统架构](/zh/ref/trading-architecture/)。

## 1. 常用 Level-2 因子：定义、状态、和研究侧对不上的地方 {#factors}

> **这一节解决什么问题：把研究侧用 pandas 写的因子，增量地写成 C++，并且算得一样**
>
> - **因子为什么有效是研究员的事**：C++ 这一侧管的是每来一条消息怎么更新，以及结果和研究侧逐条对得上。
> - **每个因子都按四块整理**：定义，用哪类数据，C++ 要维护什么状态，和研究侧会在哪里算得不一样。
> - **前五个是单只股票的因子，覆盖三类数据**：前三个只用快照，第 4 个用逐笔成交，第 5 个用逐笔委托和逐笔成交。
> - **第 6 个是截面处理**：同一时刻把全市场的值放在一起排名或标准化，它不按消息算，按截面时刻算。

> **三个快照因子怎么分：先问看的是量还是价，再问要不要历史**
>
> - **OBI（第 1.1 节）看一张快照里的挂单量**：买方挂得多还是卖方挂得多，一张快照就能算完，不需要历史。
> - **OFI（第 1.2 节）看相邻两张快照之间买一、卖一的变化**：要记住上一张；对最近 N 张求和时，才用得上环形数组。
> - **价差突变（第 1.3 节）看前几档的价差，也就是价格**：和上一个有值的 bar 比，记住一个值就够了。

### 1.1 加权盘口不均衡（OBI）：快照 {#obi}

**定义**：买卖十档挂单量的差除以总量，离盘口越近权重越大（远端挂单撤得多，对价格影响小），$w_i$ 常取 $1/i$ 或指数递减：

$$\text{OBI}=\frac{\sum_{i=1}^{10} w_i\,(\text{bid}_i-\text{ask}_i)}{\sum_{i=1}^{10} w_i\,(\text{bid}_i+\text{ask}_i)}$$

**数据**：只用快照，每张快照自己就能算出来。快照只有 3 秒的节拍，要逐笔级的 OBI，得用逐笔重建盘口（[交易系统架构第 6 部分](/zh/ref/trading-architecture/#book)）。

**状态**：**不需要跨消息的状态**，难点全在边界。

下面 1.1 到 1.3 三个快照因子共用这个结构体，代码按 1.1 到 1.5 的顺序接起来就能编译：

```cpp
#include <cstdint>
#include <optional>

// 一张快照：价格是放大过的整数；空档的价格和量都是 0
struct Snapshot {
    int64_t t;                       // 交易所时间，毫秒
    int64_t last;                    // 最新价，还没成交时可能是 0
    int64_t bid_px[10], bid_qty[10];
    int64_t ask_px[10], ask_qty[10];
};
```

```cpp
// 一张快照算完，不存状态；两边都没有挂单时返回空
std::optional<double> obi(const Snapshot& s) {
    double num = 0, den = 0;
    for (int i = 0; i < 10; ++i) {
        // 1. 权重 1/(i+1)，离盘口越近越大
        double w = 1.0 / (i + 1);
        num += w * double(s.bid_qty[i] - s.ask_qty[i]);
        den += w * double(s.bid_qty[i] + s.ask_qty[i]);
    }
    // 2. 分母为 0（停牌、开盘前）不能除，填什么值和研究侧约定
    if (den == 0) return std::nullopt;
    return num / den;
}
```

**和研究侧对不上的地方**：

- **涨跌停时一边全空**：涨停时卖盘全空，OBI 恒为 1，跌停恒为 −1，这段要不要用，得和研究侧约定。
- **两边都空时分母为 0**：停牌、开盘前会出现。pandas 除以 0 得到 inf 或 NaN，不报错；C++ 用整数算会直接崩，用浮点得到 nan 继续往下传。所以填什么值要事先约定。
- **集合竞价的盘口是虚拟的**：这段快照上的盘口是虚拟撮合的结果，不是连续竞价的挂单，一般剔掉（[A 股行情第 4 节](/zh/ref/a-share-market/#auction)）。
- **快照缺失**：用前值补还是留空，见[因子一致性第 2 节](/zh/ref/factor-consistency/#caliber)。

### 1.2 订单流不平衡（OFI）：相邻两张快照 {#ofi}

**定义**：OBI 看的是盘口上挂着多少，OFI 看的是两张快照之间买一、卖一多了多少、少了多少。**OBI 是存量，OFI 是流量**。买方这一边按买一价怎么动分三种情况：

$$e^{b}_t=\begin{cases}q^{b}_t & P^{b}_t \gt P^{b}_{t-1}\\ q^{b}_t-q^{b}_{t-1} & P^{b}_t=P^{b}_{t-1}\\ -q^{b}_{t-1} & P^{b}_t \lt P^{b}_{t-1}\end{cases}$$

- **买一价上移**：新买一上的挂单全是新出现的，整档都算新增买压。
- **买一价不变**：看这一档的量增加还是减少。
- **买一价下移**：原来那一档被吃光或撤光了，整档都算减少。

卖方镜像：卖一价下移时整档算新增卖压，上移时整档算减少，记作 $e^{a}_t$。卖压对价格的作用和买压相反，所以相减，再对最近 N 张快照求和：

$$e_t=e^{b}_t-e^{a}_t,\qquad \text{OFI}_t=\sum_{k=t-N+1}^{t}e_k$$

**数据**：只用快照的买一、卖一，但要相邻两张一起看。

**状态**：两部分。一是上一张快照的买一价、买一量、卖一价、卖一量；二是最近 N 个 $e$ 的环形数组和它们的累加和。来一张快照，先和上一张比出 $e_t$，加进累加和，再减掉被挤出窗口的那个，最后把这张的买一卖一存下来。**$e$ 是整数，累加和一加一减不会有误差**；容量取 2 的幂，下标用按位与回绕。

```cpp
struct Ofi {
    static constexpr int N = 64;     // 窗口张数，取 2 的幂
    int64_t ring[N] = {};            // 最近 N 个 e
    int64_t sum = 0;                 // ring 里 N 个 e 的和
    int64_t count = 0;               // 一共算出过几个 e
    bool has_prev = false;
    int64_t pb = 0, qb = 0, pa = 0, qa = 0;   // 上一张的买一价、买一量、卖一价、卖一量

    // 窗口还没攒满 N 个 e 时返回空，对应 pandas rolling(N) 开头的 NaN
    std::optional<int64_t> on_snapshot(const Snapshot& s) {
        int64_t b = s.bid_px[0], vb = s.bid_qty[0];
        int64_t a = s.ask_px[0], va = s.ask_qty[0];
        // 1. 第一张没有上一张，只存下来，不能拿 0 当上一张
        if (!has_prev) {
            has_prev = true;
            pb = b; qb = vb; pa = a; qa = va;
            return std::nullopt;
        }
        // 2. 买方：价上移整档算新增，价不变看量差，价下移整档算减少
        int64_t eb = b > pb ? vb : (b == pb ? vb - qb : -qb);
        // 3. 卖方镜像：价下移整档算新增卖压
        int64_t ea = a < pa ? va : (a == pa ? va - qa : -qa);
        int64_t e = eb - ea;
        // 4. 进一个加、出一个减；没满时被覆盖的格子是 0，减了也不影响
        //    下标用按位与回绕，所以 N 要是 2 的幂
        int64_t& slot = ring[count & (N - 1)];
        sum += e - slot;
        slot = e;
        ++count;
        // 5. 存下这一张，下一张和它比
        pb = b; qb = vb; pa = a; qa = va;
        if (count < N) return std::nullopt;
        return sum;
    }
};
```

**和研究侧对不上的地方**：

- **第一张快照没有上一张**：pandas 里 `shift(1)` 得到 NaN，这一行自然空着；C++ 要显式跳过，不能拿 0 当上一张，否则第一张的买一卖一会整档算成新增。
- **窗口按张数还是按时间**：快照没有变化通常不推（[因子一致性第 2 节](/zh/ref/factor-consistency/#caliber)），所以 N 张快照跨多长时间是不固定的。研究侧如果先补成每 3 秒一行再 `rolling(N)`，补出来的行 $e=0$，但会占窗口里的位置，C++ 也得照着补。
- **跨过集合竞价和午休**：9:30 第一张快照的“上一张”是集合竞价的虚拟盘口，13:00 第一张的“上一张”是 11:30 那张，要不要比得和研究侧约定。
- **涨跌停**：一边没有挂单，价格是 0 或空，上面三种情况的比较会跳到“整档新增”或“整档减少”，这段一般剔掉。
- **多档 OFI**：研究侧可能对前几档各算一个 $e$ 再加权，C++ 的状态就变成每一档一组价和量。

### 1.3 加权价差突变：快照，和上一个有值的 bar 比 {#spread-jump}

**定义**：OBI 和 OFI 都看挂单量，这个因子看价格：前 N 档的相对价差突然变宽还是变窄。大单扫掉一档、或者一侧挂单被撤走时，价差会一下子拉开。每个 bar 先算前 N 档的加权相对价差，离盘口越近权重越大，$w_i$ 常取 $N+1-i$：

$$s_t=\frac{\sum_{i=1}^{N} w_i\,(\text{ask}_i-\text{bid}_i)/P_{\text{last}}}{\sum_{i=1}^{N} w_i}$$

因子值是这个 bar 和前面最近一个有值的 bar 的差：$\Delta s_t=s_t-s_{\text{prev}}$。

**数据**：快照，按时间切成 3 秒一个的 bar，同一个 bar 里来了几张快照，后面的覆盖前面的。

**状态**：当前 bar 的编号和值，前面最近一个有值的 bar 的值，再加一个最近不为 0 的最新价，用来补 0。进入新的 bar 时，把上一个 bar 的值留作 $s_{\text{prev}}$。**它只和前一个值比，不需要环形数组**；要输出过去 N 个 bar 的均值或和，才需要。

```cpp
struct SpreadJump {
    static constexpr int N = 5;              // 用前 5 档
    static constexpr int64_t BAR_MS = 3000;  // 3 秒一个 bar
    int64_t bar = -1;                        // 当前 bar 编号
    bool cur_ok = false;                     // 当前 bar 有没有值
    double cur = 0;                          // 当前 bar 的值，同一个 bar 里后来的覆盖前面的
    bool has_prev = false;
    double prev = 0;                         // 前面最近一个有值的 bar 的值
    int64_t last_px = 0;                     // 最近一个不为 0 的最新价

    // 返回当前 bar 的因子值；前面还没有有值的 bar 时返回空
    std::optional<double> on_snapshot(const Snapshot& s) {
        // 1. 这张快照落在哪个 bar；进了新 bar，上一个 bar 有值就留作 prev
        //    没有值的 bar 跳过，prev 还是更早那个（对应 pandas 先 dropna 再 diff）
        int64_t b = s.t / BAR_MS;
        if (b != bar) {
            if (cur_ok) { prev = cur; has_prev = true; }
            bar = b;
            cur_ok = false;
        }
        // 2. 最新价是 0 就用之前的；之前也没有，就用买一卖一的中间价
        if (s.last > 0) last_px = s.last;
        int64_t px = last_px > 0 ? last_px : (s.bid_px[0] + s.ask_px[0]) / 2;
        // 3. 前 N 档的相对价差，权重 N, N-1, ..., 1；一边空着的档跳过，权重也不计
        double num = 0;
        int den = 0;
        for (int i = 0; i < N && px > 0; ++i) {
            if (s.bid_px[i] == 0 || s.ask_px[i] == 0) continue;
            int w = N - i;
            num += w * double(s.ask_px[i] - s.bid_px[i]) / double(px);
            den += w;
        }
        // 4. 这张算不出来，就不覆盖这个 bar 已有的值
        if (den > 0) { cur = num / den; cur_ok = true; }
        if (!cur_ok || !has_prev) return std::nullopt;
        return cur - prev;
    }
};
```

**和研究侧对不上的地方**：

- **“前面最近一个有值的 bar”在 pandas 里有两种写法，结果不一样**：先 `ffill()` 再 `diff()`，空 bar 得到 0，下一个有值的 bar 和补出来的值比；先 `dropna()` 再 `diff()`，空 bar 留空，下一个有值的 bar 和更早那个真实的值比。C++ 要照研究侧用的那一种写。
- **最新价是 0**：开盘后还没有成交，或者数据商没填，分母为 0。用上一个 bar 的最新价补，还是用买一卖一的中间价，要约定。
- **某一档一边是空的**：涨跌停或者盘口很薄时，那一档的价差没有意义。跳过这一档、权重也从分母里去掉，还是整张快照作废，要约定。
- **同一个 bar 里有几张快照**：取最后一张还是取平均，要和研究侧一致；最后一张最常见，也最省状态。
- **跨午休**：13:00 第一个 bar 和 11:30 最后一个 bar 比不比，要约定。

### 1.4 主动大单净流入：逐笔成交 {#big-order}

**定义**：大单的主动买入额减去主动卖出额，除以同期总成交额。把窗口里每一笔主动委托 $k$ 引发的成交加起来，得到它的成交额 $A_k$；主动买记 $d_k=+1$，主动卖记 $d_k=-1$；$H$ 是大单门槛：

$$A_k=\sum_{j\in k}p_j\,q_j,\qquad \text{大单净流入}=\frac{\sum_{k:\,A_k\ge H}d_k\,A_k}{\sum_{j}p_j\,q_j}$$

分母是窗口里所有成交的金额，深圳的撤单和集合竞价的成交都不算在内。

**大单要按委托分，不能按单笔成交分**：一张大买单吃掉卖一到卖五，会拆成很多笔小成交，按单笔金额分档，它就被算成一堆小单。所以要先按主动方的委托把成交累加起来：上海看 B/S 标志，B 取买方订单号、S 取卖方订单号；深圳比较买卖双方的委托序号，取大的那个（[A 股行情 3.4](/zh/ref/a-share-market/#aggressor)）。

**数据**：只用逐笔成交。

**状态**：很省。一笔主动委托到达后立即撮合，它引发的成交在序号上是连续的，所以**看到主动方的委托号变了，就可以结算上一笔**：累计金额过门槛就记大单，再加进主动买或主动卖的累加和。如果研究侧连被动方也按委托大小分档，就得再维护一张“委托号 → 累计成交额”的哈希表，委托全部成交或撤单后删掉，否则表一天下来只增不减。

```cpp
// side：'B' 主动买，'S' 主动卖，'N' 集合竞价没有主动方
// 上海直接用内外盘标志；深圳先比较买卖双方委托序号，大的一方是主动方
struct Trade { int64_t px, qty, bid_no, ask_no; char side; };

struct BigOrderFlow {
    int64_t threshold;                   // 大单门槛，按一笔主动委托的累计成交金额
    int64_t cur_no = -1;                 // 正在累加的那笔主动委托
    char cur_side = 0;
    int64_t cur_amt = 0;
    int64_t big_buy = 0, big_sell = 0, total = 0;

    void on_trade(const Trade& x) {
        // 1. 深圳的撤单（价格 0）和集合竞价的成交都不算
        if (x.px == 0 || x.side == 'N') return;
        int64_t amt = x.px * x.qty;
        total += amt;
        // 2. 主动委托号变了，说明上一笔主动委托的成交已经出完，结算它
        //    一笔主动委托引发的成交在序号上是连续的，所以不用哈希表
        int64_t no = x.side == 'B' ? x.bid_no : x.ask_no;
        if (no != cur_no) {
            settle();
            cur_no = no;
            cur_side = x.side;
        }
        cur_amt += amt;
    }
    void settle() {
        if (cur_amt >= threshold) (cur_side == 'B' ? big_buy : big_sell) += cur_amt;
        cur_amt = 0;
    }
    // 当日到现在的值；正在累加的那笔按已有金额算进去，但不结算它
    std::optional<double> value() const {
        if (total == 0) return std::nullopt;
        int64_t bb = big_buy, bs = big_sell;
        if (cur_amt >= threshold) (cur_side == 'B' ? bb : bs) += cur_amt;
        return double(bb - bs) / double(total);
    }
};
```

**和研究侧对不上的地方**：

- **深圳的逐笔成交里混着撤单**：撤单的价格是 0，要先滤掉，否则撤单量会被当成交量累加。
- **“委托多大”有两种口径**：按原始委托金额，还是按实际成交金额。深圳逐笔委托有原始数量；上海立即全部成交的单在逐笔委托里查不到，只能用成交金额，所以两市口径要统一。
- **集合竞价的成交没有主动方**：要剔掉（[A 股行情 3.4](/zh/ref/a-share-market/#aggressor)）。

### 1.5 撤单金额占比：逐笔委托和逐笔成交 {#cancel-ratio}

**定义**：一段时间内被撤掉的委托金额，除以同期新增委托金额。撤单 $c$ 的价格 $p_c$ 是它原委托的价格，$q_c$ 是撤掉的数量；新委托 $o$ 的价格和数量是 $p_o$、$q_o$：

$$\text{撤单占比}=\frac{\sum_{c\in\text{撤单}}p_c\,q_c}{\sum_{o\in\text{新委托}}p_o\,q_o}$$

**数据**：逐笔委托和逐笔成交都要用，分子在两市的来源不同。

- **上海**：删除记录在逐笔委托里，自带价格和被删的剩余量，直接乘。
- **深圳**：撤单在逐笔成交里，价格是 0，只有数量，要用不为 0 的那个委托序号查回原委托，才知道撤的是哪个价位、哪一边。

**状态**：**C++ 要维护一张“委托号 → 价格、剩余量”的表**，委托全部成交或撤掉就删。下面是深圳版；上海的删除记录自带价格，`on_cancel` 直接用记录里的价格就行，不用查表。

```cpp
#include <unordered_map>
#include <utility>

struct CancelRatio {
    // 委托号 → (价格, 剩余量)；全部成交或撤掉就删，表才不会一天只增不减
    std::unordered_map<int64_t, std::pair<int64_t, int64_t>> live;
    int64_t new_amt = 0, cancel_amt = 0, miss = 0;

    // 1. 新委托：金额记进分母，挂进表里
    void on_order(int64_t no, int64_t px, int64_t qty) {
        new_amt += px * qty;
        live[no] = {px, qty};
    }
    // 2. 成交：买卖两边的委托都扣掉成交量
    void on_fill(int64_t bid_no, int64_t ask_no, int64_t qty) {
        reduce(bid_no, qty);
        reduce(ask_no, qty);
    }
    // 3. 撤单：价格是 0，拿不为 0 的那个委托号查回原价
    //    查不到（比如程序 9:30 才开始收）只能计数，不能当没发生
    void on_cancel(int64_t no, int64_t qty) {
        auto it = live.find(no);
        if (it == live.end()) { ++miss; return; }
        cancel_amt += it->second.first * qty;
        reduce(no, qty);
    }
    void reduce(int64_t no, int64_t qty) {
        auto it = live.find(no);
        if (it == live.end()) return;
        it->second.second -= qty;
        if (it->second.second <= 0) live.erase(it);
    }
    std::optional<double> value() const {
        if (new_amt == 0) return std::nullopt;
        return double(cancel_amt) / double(new_amt);
    }
};
```

**和研究侧对不上的地方**：

- **C++ 只能边收边查，所以要从 9:15 开始收**：研究侧通常是全天数据按序号 merge 一次；C++ 从 9:30 才开始收的话，集合竞价里挂的单在 9:30 以后被撤，就查不到原委托了。
- **上海的分母偏小**：上海的逐笔委托不发立即全部成交的单，部分成交的只发剩余量，所以“新增委托金额”偏小，同样的撤单行为，上海算出来的占比偏高。要么用成交把上海的分母补回来，要么沪深分开标准化，选哪种得和研究侧约定。

### 1.6 截面处理：同一时刻把全市场放在一起比 {#cross-section}

**定义**：前五个都是一只股票自己的时间序列。研究侧拿到这些值后，通常还要在同一时刻把全市场的股票放在一起，做排名或标准化，得到的才是最后用的因子。设某一时刻有值的股票有 $n$ 只，第 $i$ 只的值是 $x_i$：

$$\text{rank}^{\text{pct}}_i=\frac{\text{第 } i \text{ 只的名次}}{n},\qquad z_i=\frac{x_i-\bar{x}}{s},\quad s=\sqrt{\frac{1}{n-1}\sum_{j=1}^{n}(x_j-\bar{x})^2}$$

名次从小到大数，值相同的几只取它们名次的平均。

**数据**：不是新的行情，是 1.1 到 1.5 这些单股票因子在同一时刻的值，一只股票一个。

**状态**：每个截面时刻一个长度为股票数的数组，每只股票往自己的格子里写最新值，到了截面时刻整列算一次。**截面不能增量算**：一只股票的值变了，所有股票的名次和标准分都可能跟着变。所以它不放在 `on_snapshot` 里每条消息算，而是在 bar 结束、或者定时器到点时一次算完。全市场 5000 只左右，排一次序很快，代价是按截面时刻算的，不是按消息。

```cpp
#include <algorithm>
#include <cmath>
#include <vector>

// 截面百分位排名：同值取平均名次，NaN 不参与、保持 NaN，和 pandas rank(pct=True) 一样
std::vector<double> cs_rank_pct(const std::vector<double>& x) {
    // 1. 只把有值的下标拿出来，按值排序
    std::vector<int> idx;
    for (int i = 0; i < (int)x.size(); ++i)
        if (!std::isnan(x[i])) idx.push_back(i);
    std::sort(idx.begin(), idx.end(), [&](int a, int b) { return x[a] < x[b]; });
    // 2. 一段相同的值共享平均名次：排在第 i+1 到第 j 位，平均是 (i+1+j)/2
    //    百分位除以有值的个数 n，不是股票总数
    std::vector<double> r(x.size(), NAN);
    int n = (int)idx.size();
    for (int i = 0; i < n;) {
        int j = i;
        while (j < n && x[idx[j]] == x[idx[i]]) ++j;
        double avg = (i + 1 + j) / 2.0;
        for (int k = i; k < j; ++k) r[idx[k]] = avg / n;
        i = j;
    }
    return r;
}

// 截面标准化：减均值、除以标准差；标准差按 ddof=1，和 pandas std() 默认一样
std::vector<double> cs_zscore(const std::vector<double>& x) {
    // 1. 只用有值的股票算均值
    double sum = 0;
    int n = 0;
    for (double v : x)
        if (!std::isnan(v)) { sum += v; ++n; }
    std::vector<double> z(x.size(), NAN);
    if (n < 2) return z;
    double mean = sum / n;
    // 2. 再扫一遍算标准差；一次算完整个截面，用两遍扫描比“平方和减和的平方”稳
    double ss = 0;
    for (double v : x)
        if (!std::isnan(v)) ss += (v - mean) * (v - mean);
    double sd = std::sqrt(ss / (n - 1));
    // 3. 所有值都一样时标准差为 0，没法除，整列留 NaN
    if (sd == 0) return z;
    for (size_t i = 0; i < x.size(); ++i)
        if (!std::isnan(x[i])) z[i] = (x[i] - mean) / sd;
    return z;
}
```

**和研究侧对不上的地方**：

- **同值的名次**：pandas `rank()` 默认同值取平均名次；C++ 里排完序直接用下标当名次，同值的几只会拿到不同的名次。
- **百分位的分母**：`rank(pct=True)` 除以有值的股票数，不是股票总数。停牌的股票是 NaN，不参与排名，也不占分母。
- **标准差的自由度**：pandas `std()` 默认 `ddof=1`，除以 $n-1$；`numpy.std` 默认 `ddof=0`，除以 $n$。研究侧用的是哪一个，C++ 就照着写。
- **股票池**：同一时刻哪些股票参与比，ST、停牌、上市不满一段时间的新股、涨跌停的要不要剔掉，两边要用同一份名单。剔掉的股票是 NaN，不能填 0，填 0 会被当成一个真的值参与排名。
- **处理顺序**：常见的流程是先去极值（比如中位数加减几倍 MAD 截断），再标准化，再做行业中性化。顺序换了，结果就不一样。
- **截面时刻怎么取值**：研究侧是整张表按时刻对齐好的；实盘到了截面时刻，有的股票这个 bar 还没有新快照，用它上一个值还是记 NaN，要和研究侧的补法一致（[因子一致性第 2 节](/zh/ref/factor-consistency/#caliber)）。
- **编译选项**：开了 `-ffast-math`，编译器会假设没有 NaN，`std::isnan` 可能直接被优化成 `false`，NaN 就混进排名里了。用到 NaN 判断的代码不能开它。

## 2. 流合并、时序对齐、增量计算 {#stream}

**痛点**：

- 研究员的因子回测好好的，搬到 C++ 实盘，同一天的数据两边算出来对不上。
- 根子是算法的形状不一样。研究侧是批处理：拿一整天的数据，先把几张表按时间拼好，再用 pandas 对整列一次算完。C++ 实盘是流式处理：数据一条一条到，每来一条就要给出当前的因子值。

从批处理改成流式，有三件事要重新做一遍：几路数据按什么顺序进来（流合并），不同节拍的数据怎么放到同一个时刻上（时序对齐），每来一条怎么更新、而不是把窗口重算一遍（增量计算）。**三件事都会让 C++ 和 pandas 算得不一样，而且差在边界上，平时看不出来**。

### 2.1 流合并：多路数据合成一条流 {#merge}

**痛点**：

- 全市场因子（比如“过去 1 分钟全市场主动买入额”）要用沪深所有通道的成交。
- 每个通道内部按序号有序，但通道之间没有共同的序号，谁先谁后没有人告诉你。
- 合并的顺序不同，因子在某个时刻的值就不同。研究侧和实盘合并的方式不一样，两边就对不上。

先说什么时候不用合并。同一个通道里，委托和成交共用一套序号，按序号排就是交易所的处理顺序（[A 股行情 3.1](/zh/ref/a-share-market/#seq-order)）。单只股票只在一个通道里，所以**只用一只股票自己数据的因子，按序号处理就够了，用不着合并**。

要合并的是跨通道、跨品种的数据：沪深两市、同一市场的多个通道、快照和逐笔、股指期货。它们之间没有共同的序号，只能按时间戳合并。做法是多路归并：每一路各自已经有序，用一个小顶堆每次取时间戳最小的那一条。

麻烦在于时间戳相同的时候。不同通道同一毫秒的两条消息，谁先处理没有标准答案。对有状态的因子（比如全市场主动买入额的滚动和），先后不同，中间结果就不同。所以要定一个固定的规则，比如时间戳相同时按市场、通道号、序号排，并且研究侧用同样的规则。

还有一个更根本的差别：用哪个时间。研究侧通常按交易所时间合并；实盘里，你只能按消息到达的先后处理。两个通道的消息走不同的线路，到达的先后和交易所时间的先后不一定一致。想严格按交易所时间排，就得攒一小段再排序，代价是延迟。一般的做法是实盘按到达顺序处理，回测时知道这里有一点差别。

### 2.2 时序对齐：不同节拍放到同一个时刻上 {#align}

**痛点**：

- 不同数据节拍不同：快照约 3 秒一张，逐笔随时来，股指期货的行情约 500 ms 一张，时间戳几乎从不相等。
- 因子要用“股票快照时刻的期货价格”，就得决定在 9:31:02 这个时刻，期货价格取哪一张。
- 研究侧一句 merge 就带过去了。方向取错就是用了未来的数据，回测很好看，实盘复现不了。

**规则只有一条：每个时刻只能用那时已经知道的数据**。所以取的是时间戳不晚于 9:31:02 的最近一条，pandas 里是 `merge_asof`（默认就是往前找）。用插值，或者取之后最近的一条，都是在用未来的数据，回测会好看，实盘做不到。

最常见的踩坑是 bar 的标签。把逐笔按 1 分钟切成 bar，pandas `resample("1min")` 默认左闭、标签取左端：标着 9:31 的那根 bar，装的是 9:31:00 到 9:32:00 的成交。如果策略在 9:31 就用这根 bar，等于提前一分钟看到了数据。很多数据商的分钟线反过来，按结束时间标，9:31 那根装的是 9:30 到 9:31。C++ 切 bar 时，开闭和标签都要和研究侧用的数据一致，集合竞价和午休怎么切见第 4、5 节。

另一个选择是采样方式。按时间采样（每 3 秒、每 1 分钟）最常见；也有按成交量或笔数采样的，比如每成交 10 万股算一根 bar，活跃的时候 bar 多，冷清的时候 bar 少。C++ 的因子通常每条消息都更新，但输出要按研究侧的采样点取值。

### 2.3 增量计算：每来一条，只算变化的部分 {#incremental}

**痛点**：

- 太慢：研究侧写一行 `df["amount"].rolling("5min").sum()`，pandas 对整列算一次；实盘每来一笔成交都要输出新值，5 分钟里可能有几千笔，每笔都重新加一遍来不及。
- 对不上：改成增量写法以后，窗口边界、开头几条、数值精度，很容易和 pandas 的默认行为不一样，而且差别只在开盘和窗口边上冒出来。

增量的做法是：新的一条加进来，掉出窗口的从头上减掉，每条消息的工作量和窗口大小无关。

```cpp
#include <cstdint>
#include <deque>
#include <utility>

// 最近 W 毫秒内的成交额之和，窗口是 (t - W, t]，和 pandas rolling("5min") 默认的右闭一样
struct RollingSum {
    int64_t window_ms;
    std::deque<std::pair<int64_t, int64_t>> q;   // (时间戳, 金额)
    int64_t sum = 0;

    int64_t update(int64_t ts, int64_t amount) {
        q.emplace_back(ts, amount);
        sum += amount;
        while (q.front().first <= ts - window_ms) {   // 掉出窗口的，从头上减掉
            sum -= q.front().second;
            q.pop_front();
        }
        return sum;
    }
};
```

写法不难，和 pandas 对不上的地方在下面几处：

- 窗口边界。按时间的窗口，pandas 默认是左开右闭 $(t-W,\,t]$：正好 5 分钟前的那一条不算。C++ 里 `<=` 写成 `<`，就多算一条。
- 窗口开头。按条数的窗口 `rolling(20)`，不满 20 条时 pandas 输出 NaN；C++ 很容易直接输出前几条的结果。开盘头几条输出什么，要约定。
- 浮点误差。加一条、减一条，一天几百万次下来，浮点和会慢慢漂；pandas 的滚动求和内部做了误差补偿，两边会差在最后几位。价格和金额本来就是放大过的整数（[因子一致性第 2 节](/zh/ref/factor-consistency/#caliber)），用 `int64_t` 累加就完全精确。方差不要用“平方和减和的平方”，两个大数相减会丢精度，用 Welford 的增量公式。
- 最大最小值。最大值不能减掉，掉出窗口的那条如果正好是最大值，就得知道第二大的是谁。做法是单调队列：队列里只留“比后来者都大”的元素，每条消息平均 O(1)。
- 指数加权。`ewm(alpha=a).mean()` 默认 `adjust=True`，前面几条按归一化的权重算；C++ 常写的递推 $y_t = a\,x_t + (1-a)\,y_{t-1}$ 对应的是 `adjust=False`。两者开头差得多，越往后越接近。

**所以把研究侧的因子改成增量版，第一件事是逐条对一遍：拿同一天的数据，C++ 每条输出和 pandas 那一列逐行比**。差别集中在开头和边界上，看差在哪几行，基本就知道是上面哪一处。

## 3. 手写因子：先说状态，再写代码 {#write}

> **这一节解决什么问题：拿到一个因子定义，把它写成实时计算**
>
> - **难点是状态设计，不是公式**：公式一两行就写完了，要想清楚的是每只股票存什么、消息来了改什么、什么时候输出、哪些东西能共用。
> - **“输入整个数组、输出一个值”的函数在实盘用不上**：那是 pandas 的写法。实盘数据一条一条来，每来一条都要给出当前的值，所以要写成流式。

### 3.1 on_tick 和 on_trade：谁在什么时候调你 {#callbacks}

**这些函数不是你自己调的，是行情框架收到一条数据后回调你的**。一般的约定是每种消息一个回调，名字就叫那种消息，来一条什么消息就调哪一个：

| 回调 | 什么时候被调 | A 股 Level-2 里对应什么 |
|---|---|---|
| `on_tick` / `on_snapshot` | 来了一张行情快照，盘口变了 | 约 3 秒一张的十档快照 |
| `on_trade` | 来了一笔成交 | 逐笔成交 |
| `on_order` | 来了一笔委托 | 逐笔委托 |
| `on_timer` / `on_bar` | 到了约定的时刻，或者一根 bar 结束 | 不是行情，是定时器 |

**“tick”这个词本身很宽**：广义上任何一条行情更新都叫一个 tick，快照、成交都算，所以有的框架只有一个 `on_tick`，成交和快照都从这里进来，再按类型分发。所以泛泛地说“on_tick”，意思通常只是“数据来一条，函数被调一次”，不是指某个固定的接口。

**真正要分清的是两类事件**：

- **数据到了**：快照、成交、委托到达，回调里只改状态。
- **要值了**：策略在某个时刻要一个因子值。这个时刻可能正好是一笔成交到达，也可能是一张快照、一个定时器，和成交没有关系。

下面是一只股票的一段时间线，只有成交的因子（比如 3.4 的 VWAP），在快照时刻取值：

| 时刻 | 来了什么 | 被调的回调 | 因子做什么 |
|---|---|---|---|
| 09:30:01.100 | 成交 | `on_trade` | 加进窗口 |
| 09:30:02.450 | 成交 | `on_trade` | 加进窗口 |
| 09:30:03.000 | 快照 | `on_snapshot` | `query(09:30:03.000)`：剔掉过期的，算出值 |
| 09:30:04.900 | 成交 | `on_trade` | 加进窗口 |
| 09:30:06.000 | 快照 | `on_snapshot` | `query(09:30:06.000)` |

**成交和快照各来各的，`query` 挂在哪个回调里，取决于什么时候要值**。

### 3.2 一个因子怎么写：一个写入口，一个读入口 {#template}

**每个因子都是这个形状**：状态放在一个结构体里，数据来了走写入口，要值了走读入口。

```cpp
struct Factor {
    // 1. 状态：窗口里的数据、累加和、上一条，因子要什么存什么

    // 2. 写入口：数据来了只改状态，不输出
    void on_trade(const Trade& x);

    // 3. 读入口：要值了，先剔掉过期的，再算；没有值返回空
    std::optional<double> query(int64_t T);
};
```

**回调按数据类型起名，名字不跟着输出方式变**：`on_trade` 就是“成交来了”，`on_snapshot` 就是“快照来了”。要不要顺手返回因子值，只看什么时候要值，名字不变。这样一看函数名就知道它在什么时候被调；`on_tick` 只在框架把所有行情都从一个口子送进来时才用。

**什么时候合成一个函数，看“什么时候要值”**：

- **每来一条数据就要一个值**：查询时刻就是这条数据的时间，写入口里加完、以这条的时间剔除、算完直接返回，不用 `query`。数据是成交，这个函数还叫 `on_trade`；数据是快照，就叫 `on_snapshot`。第 1 节的 OBI、OFI、价差突变都是这种，`on_snapshot` 的返回值就是因子值。
- **按固定时刻采样**：一定要拆成两个。只有写入口的话，一段时间没有新数据，回调就不会被调，窗口里过期的数据没人剔除，取到的还是很久以前的值。

**写的顺序：先空壳，再填一个，最后补边界**。

1. 先写结构体和两个入口的签名，函数体空着。
2. 再填写入口和读入口。
3. 最后补边界：第一条、空窗口、分母为 0。

**多只股票、多个因子时，外面再套两层**：每只股票一个状态对象，把用同一类数据的因子放在一起，一条消息进来挨个更新；引擎按股票编号分发。加一个因子只动里面两层。只有一只股票、一个因子时，因子这一层就够了，外面两层只是转发。

```cpp
#include <vector>

// 1. 每只股票一个状态对象：用同一类数据的因子放在一起
struct SymbolState {
    Ofi ofi;
    SpreadJump spread;
    BigOrderFlow big{5'000'000};
    // 最近一次算出的值，查询时直接读
    std::optional<double> obi_v, spread_v;
    std::optional<int64_t> ofi_v;

    // 2. 一张快照进来，用快照的因子各更新一次
    void on_snapshot(const Snapshot& s) {
        obi_v = obi(s);
        ofi_v = ofi.on_snapshot(s);
        spread_v = spread.on_snapshot(s);
    }
    // 3. 一笔成交进来，用成交的因子各更新一次
    void on_trade(const Trade& x) { big.on_trade(x); }
};

// 4. 引擎只做一件事：按股票分发
//    开盘前给每只股票编好号，热路径上用下标，不查字符串
struct Engine {
    std::vector<SymbolState> states;
    explicit Engine(int n_symbols) : states(n_symbols) {}
    void on_snapshot(int sym, const Snapshot& s) { states[sym].on_snapshot(s); }
    void on_trade(int sym, const Trade& x) { states[sym].on_trade(x); }
    const SymbolState& get(int sym) const { return states[sym]; }
};
```

### 3.3 动手前先定五件事 {#five}

1. **输入**：每条消息长什么样，只列这个因子用得到的字段；时间是什么单位，价格是不是放大过的整数。
2. **状态**：每只股票一个状态对象，里面存什么，为什么这些就够了。比如 OFI 存上一张快照的买一卖一，加一个 N 格的环形数组和它的和。
3. **更新顺序**：一条消息来了，先改什么、后改什么。比如 OFI 先和上一张比出 $e$，再更新窗口，最后存下这一张；时间窗口先加新的，查询时再剔过期的。
4. **输出时机**：每条消息都要值，还是在给定时刻采样。这一句决定写一个入口还是两个（3.2）。
5. **边界**：第一条、窗口为空、分母为 0、涨跌停，各返回什么。

### 3.4 例子：60 秒时间窗口的 VWAP 和平均每笔成交量 {#vwap}

**要求**：一只股票的逐笔成交按时间有序到来，每条是（时间，价格，数量），数量都大于 0。在任意采样时刻 $T$，输出窗口 $(T-60\text{s},\,T]$ 内的两个因子：

$$\text{VWAP}=\frac{\sum \text{价}\times\text{量}}{\sum \text{量}},\qquad \text{平均每笔成交量}=\frac{\sum \text{量}}{\text{笔数}}$$

**先定三件事**：

- **时间是什么单位**：毫秒的话，窗口是 `60'000`，不是 `60`。
- **什么时候要值**：要求是“任意采样时刻”，所以要两个入口；如果是每笔成交都要值，就合成一个。
- **窗口里没有成交时返回什么**：返回 0 看起来像一个真的值，用 `optional` 表示没有值，或者和调用方约定一个值。

**设计**：

- **状态**：窗口里成交的队列，Σ价×量，Σ量。笔数就是队列长度，不用另记。
- **成交来了**：入队，两个和各加一次。
- **查询时刻 T**：先把 `t <= T - 60s` 的从队头弹出、从两个和里减掉，再算。
- **共用**：Σ量两个因子都要，只维护一份。

```cpp
#include <cstdint>
#include <deque>
#include <optional>

struct Trade { int64_t t, px, qty; };   // t 毫秒；px 放大过的整数

struct Window60s {
    static constexpr int64_t W = 60'000;
    std::deque<Trade> q;                // 窗口里的成交，队头最旧
    int64_t sum_pq = 0, sum_q = 0;      // 整数累加，加进去再减出来一位不差

    // 1. 写入口：入队，两个和各加一次
    void on_trade(const Trade& x) {
        q.push_back(x);
        sum_pq += x.px * x.qty;
        sum_q += x.qty;
    }
    // 2. 剔除过期的：窗口左开右闭，正好 60 秒前的那一笔也要出去，所以是 <=
    void evict(int64_t T) {
        while (!q.empty() && q.front().t <= T - W) {
            sum_pq -= q.front().px * q.front().qty;
            sum_q -= q.front().qty;
            q.pop_front();
        }
    }
    // 3. 读入口：先剔除，再判空，再算
    std::optional<double> vwap(int64_t T) {
        evict(T);
        if (q.empty()) return std::nullopt;
        return double(sum_pq) / double(sum_q);
    }
    std::optional<double> avg_qty(int64_t T) {
        evict(T);
        if (q.empty()) return std::nullopt;
        return double(sum_q) / double(q.size());
    }
};
```

**如果是每笔成交都要值**，`on_trade` 直接返回两个因子，`vwap`、`avg_qty` 两个读入口就不要了：加完以这笔的时间剔除，刚放进一笔，窗口不会是空的，连判空都省了。

```cpp
// 每来一笔成交：加进窗口，以这笔的时间为 T，返回 (VWAP, 平均每笔成交量)
std::pair<double, double> on_trade(const Trade& x) {
    // 1. 入队，两个和各加一次
    q.push_back(x);
    sum_pq += x.px * x.qty;
    sum_q += x.qty;
    // 2. 查询时刻就是这笔的时间
    evict(x.t);
    // 3. 窗口里至少有刚放进的这一笔
    return {double(sum_pq) / double(sum_q), double(sum_q) / double(q.size())};
}
```

**怎么验证**：暴力版每次把全部成交扫一遍，O(n)，拿它当标准答案，随机造一串成交和查询时刻，两边逐个比，窗口边界上正好 60 秒前的那一笔要专门造出来。

### 3.5 写完怎么证明它对 {#verify}

- **和暴力解对拍**：同一串数据，暴力版每次把窗口重算一遍，增量版逐条输出，两边逐条比。
- **手造几个边界**：第一条消息、正好落在窗口边界上的那一条、窗口为空、最新价是 0。
- **和研究侧对**：拿同一天的数据，C++ 每条输出和 pandas 那一列逐行比，差在哪几行就查第 2.3 节那几处。

### 3.6 设计上的几个问题 {#design}

- **几千只股票怎么存**：开盘前给股票编号，状态放在 `vector` 里按下标取。热路径上不用 `map<string, ...>`，查字符串又慢、又要分配内存。
- **几个因子要用同一个窗口**：窗口放在股票的状态对象里，只维护一份，几个因子都从里面读。比如 VWAP 和平均每笔成交量共用 Σ量。
- **因子接口为什么不用虚函数**：可以用，因子不多时这点开销不大。因子类型在编译期就知道的话，直接组合在结构体里（像上面那样）或者用模板，调用能内联。
- **消息乱序或重复怎么办**：同一通道按序号处理，丢了要补，重复的丢掉（[A 股行情 3.2](/zh/ref/a-share-market/#gaps)）。查询时刻 T 不回退是调用约定，要写进接口说明。
- **内存会不会一天只增不减**：按委托号建的表，委托全部成交或撤掉就删（第 1.4、1.5 节）。
- **浮点误差**：价格、金额、量用 `int64_t` 累加，最后输出时才转成 `double`（第 2.3 节）。
