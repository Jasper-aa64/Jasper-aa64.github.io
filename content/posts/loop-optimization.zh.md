先看一个点积：

```cpp
float dot(const float* v1, const float* v2, int n) {
    float sum = 0.0f;
    for (int i = 0; i < n; i++) sum += v1[i] * v2[i];
    return sum;
}
```

用 GCC 13 `-O3 -fopt-info-vec` 编译，报告写着 `loop vectorized using 16 byte vectors`。循环体：

```text
.L4:
    movups  (%rcx,%rax), %xmm1      # 读 4 个 v1
    movups  (%rsi,%rax), %xmm3      # 读 4 个 v2
    addq    $16, %rax
    mulps   %xmm3, %xmm1            # 4 个乘法一次做完
    addss   %xmm1, %xmm0            # 下面 4 个加法一个等一个
    ...shufps / unpckhps 取出第 2、3、4 个积...
    addss   %xmm2, %xmm0
    addss   %xmm2, %xmm0
    addss   %xmm1, %xmm0
    cmpq    %rdi, %rax
    jne     .L4
```

乘法 4 个一起做了，加法还是 4 条 `addss` 排队，每条都等上一条的结果。报告说“向量化了”，瓶颈没动。

> **本质：循环变换大部分编译器在 `-O3` 下自己会做，需要你管的只有两类情况**。

- **有东西挡住了编译器**：比如这里浮点加法换顺序会改变舍入结果，编译器不敢把 4 个加法并起来。
- **有些改动编译器不会替你做**：多个累加器、分块、改数据的走法，都要手写。

下面按循环慢的三类原因分节，最后讲怎么确认编译器做了什么。文中的汇编和 `-fopt-info` 输出都是 GCC 13.3、x86-64 默认 SSE2（一条向量指令处理 4 个 `float`）的实测；“快几倍”按指令延迟估算，没有计时。

## 1. 循环慢在哪：三类原因

| 原因 | 例子 | 对应的变换 |
|---|---|---|
| 每轮做了多余的事 | 不变的值每轮重算；每轮判断一个不变的条件 | 外提、强度削弱、unswitching（第 2 节） |
| 迭代之间有依赖 | 这一轮要等上一轮的结果 | 多个累加器、软件流水（第 3 节） |
| 访存走法差 | 跳着读；同一批数据反复从内存搬 | 交换、分块、融合（第 4 节） |

常听说展开能省掉 `i < n`、`i++` 的开销，这笔开销其实很小：`cmp` + `jne` 合成一条微操作，这个分支几乎每次都猜对。展开的价值是给多累加器、向量化腾地方（2.4）。

## 2. 编译器自己会做的变换

> **本质：外提、强度削弱、旋转、展开、unswitching 这五种变换，编译器基本都会自己做，不用手写**。需要注意三种让它做不成的情况：

- **调用没有内联**：编译器看不见函数体，不敢假设被调函数没改那个值。
- **两个指针可能指向同一块内存**：编译器不敢把读提到循环外面。
- **`-O2` 做得保守**：它不做 unswitching，向量化也很保守。

### 2.1 循环不变量外提（LICM）：只算一次的东西搬到循环外

每轮结果都一样的计算（数组长度、常量系数、成员变量），编译器会提到循环前只算一次。[#8 的 1.2 节](/zh/posts/crtp-static-polymorphism/)里 `sum_crtp` 的 `mult` 就被提到循环外只读一次。挡住它的两种情况：

- **调用没内联**：编译器看不见函数体，不敢假设被调函数没改那个值。#8 里的 `sum_virtual` 每轮都在被调函数里重读 `mult`。
- **指针可能重叠**：循环里通过 `int* q` 写，编译器不能确定没写到 `*p`，`*p` 就得每轮重读（[`const` 和 `constexpr`](/zh/ref/const-constexpr/#const) 里有例子）。

### 2.2 强度削弱（strength reduction）：乘法换成累加

> **本质：`a[i] = 10 * i` 这种乘以循环变量的写法，编译器会自动改成每轮加 10**。

- **`-O2` 就会换**：两种写法编出来的循环一样，都没有乘法。
- **`-O3` 还会向量化**：所以直接写 `10 * i` 就行，不用手写累加。

```cpp
void fill_10i(int* a, int n) {          // 原写法
    for (int i = 0; i < n; i++) a[i] = 10 * i;
}

void fill_10i_sr(int* a, int n) {       // 手写强度削弱
    int x = 0;
    for (int i = 0; i < n; i++) {
        a[i] = x;                       // x 始终等于 10 * i
        x += 10;
    }
}
```

实测 `-O2` 下两个函数编出来的循环一样，都没有乘法：

```text
.L3:
    movl  %eax, (%rdi)      # a[i] = x
    addl  $10, %eax         # x += 10
    addq  $4, %rdi
    cmpl  %edx, %eax
    jne   .L3
```

`x += 10` 看上去让每一轮都依赖上一轮，其实不挡并行：`x` 是**归纳变量**（每轮按固定步长变化），编译器知道第 i 轮的值就是 $10i$。`-O3` 下两种写法都向量化，一次写 4 个：

- `fill_10i_sr`：寄存器里放 `{0, 10, 20, 30}`，每轮整体加 40（`paddd`）。
- `fill_10i`：寄存器里放 `{0, 1, 2, 3}`，每轮整体加 4，再用移位和加法算出 ×10：`pslld $2`（×4）、`paddd`（加上自己，得 ×5）、`pslld $1`（×2）。

### 2.3 循环旋转（loop rotation）：`for` 变成 `do-while` 加一个前置判断

> **本质：旋转以后，只要进了循环体就保证至少执行一次，编译器把不变的计算提到循环前才安全**。

- 旋转本身不加速，它是给外提打基础。

```text
for (i = 0; i < n; i++) body;     →     if (0 < n) { i = 0; do { body; i++; } while (i < n); }
```

前面那个 `if` 叫 **loop guard**。`n` 是 0 时原来的循环一次都不执行，提出来的计算也不能执行（比如它会读一个可能无效的指针），所以外提要先旋转。汇编里的循环几乎都是这个形状：开头 `testl %edx, %edx; jle` 跳过，判断放在末尾。

### 2.4 循环展开（unrolling）：少判断几次，但不缩短依赖链

> **本质：展开只减少了循环判断的次数，依赖链一样长**。

- **展开让每轮多处理几个元素**：`i < n` 的判断因此少做几次。
- **速度不变是因为还在等**：这几次运算累加在同一个变量上，后一次照样要等前一次。
- **展开要配合别的改法才有效**：多个累加器，或者向量化。

```cpp
float dot_unroll4(const float* v1, const float* v2, int n) {
    float sum = 0.0f;
    int i = 0;
    for (; i < n - 3; i += 4) {
        sum += v1[i] * v2[i];
        sum += v1[i+1] * v2[i+1];
        sum += v1[i+2] * v2[i+2];
        sum += v1[i+3] * v2[i+3];
    }
    for (; i < n; i++) sum += v1[i] * v2[i];   // 剩下的 0–3 个
    return sum;
}
```

**只有一个 `sum`**，四个加法还是一个等一个。实测 `-O3` 下它和开头不展开的版本结构一样：乘法合成 `mulps`，加法仍是串行的 `addss`。拆成几个 `sum` 才有用（3.5）；`-O3` 下编译器自己会展开，单纯手写展开没必要。展开的宽度和向量宽度对上：SSE 一次 4 个 `float`，AVX / AVX2 8 个，AVX-512 16 个。

### 2.5 循环外提判断（loop unswitching）：不变的 `if` 提到循环外

> **本质：unswitching 省下的主要不是每轮那次判断，而是换来了向量化**。

- **判断本身几乎不花时间**：条件整个循环都不变，这个分支不会猜错。
- **判断挡住了向量化**：它留在循环里时，编译器很难把 4 轮并成一条指令。

```cpp
void add_or_sub(float* a, const float* b, int n, bool do_add) {
    for (int i = 0; i < n; i++) {
        if (do_add) a[i] += b[i];
        else        a[i] -= b[i];
    }
}
```

unswitching 就是把判断提到循环外，拆成两个各自干净的循环：`if (do_add) { 加法循环 } else { 减法循环 }`。

**`-O2` 不做**：每轮 `testb` 一次，一次只算一个：

```text
.L5:
    movss  (%rdi,%rax), %xmm0     # 读 a[i]
    movss  (%rsi,%rax), %xmm1     # 读 b[i]
    testb  %cl, %cl               # 每轮判断一次 do_add
    jne    .L10                   # 真：去 addss 那边
    subss  %xmm1, %xmm0
    movss  %xmm0, (%rdi,%rax)
    ...
```

**`-O3` 做了**：`-fopt-info-loop` 报 `unswitching loop 1 on 'if' with condition: do_add`。开头只判断一次，两份循环各自向量化：

```text
    testb  %cl, %cl               # 只判断这一次
    jne    .L3                    # 真：走加法那份
    ...                           # 假：走减法那份（结构一样，用 subps）
.L16:                             # 加法那份的主循环，一次 4 个
    movups (%rax,%rcx), %xmm0
    movups (%rsi,%rcx), %xmm3
    addps  %xmm3, %xmm0
    movups %xmm0, (%rax,%rcx)
    addq   $16, %rcx
    cmpq   %rdi, %rcx
    jne    .L16
```

- **每份进循环前还会比较 `a`、`b` 的地址**：重叠走逐个算的版本，不重叠才走向量版。这是循环多版本（[#10 的 1.2 节](/zh/posts/pointer-memory-access/)），和 unswitching 是两回事。
- **`-O2` 下手写拆开**（或者把 `do_add` 做成模板参数），能去掉每轮的判断，但实测仍然不向量化，因为 `-O2` 的向量化很保守（第 6 节）。两样都要，就用 `-O3`。代价是代码多了一份。

## 3. 执行单元、指令级并行和依赖链：耗时由最长的那条链决定 {#dependency-chains}

以开头点积里的求和为例：

```cpp
for (int i = 0; i < n; ++i) s += x[i];
```

- **依赖链是首尾相接的一串指令**：每轮的 `s += x[i]` 要用上一轮加完的 `s`，前一条的结果是后一条的输入。
- **链上的时间只能相加**：一次浮点加法约 4 个周期，$n$ 个元素至少要 $4n$ 个周期；硬件每周期能开始 2 次加法（3.1），这里只用上了八分之一。
- **多累加器把一条链拆成几条**：加法次数不变，几条链同时在执行单元里，见下图。

### 3.1 执行单元：同一类运算电路复制几份，每份切成几级流水 {#execution-units}

> **本质：同一时刻能有几条运算在执行，取决于两件事：同一类执行单元有几个，每个执行单元内部切成了几段流水线**。

- **同一类执行单元有好几个**：比如两个 FMA 单元，每周期能各开始一条运算。
- **每个执行单元内部也是流水线**：这和取指、译码、执行、退休那条核的流水线是两层。一条浮点加法进了加法器，还要走 4 段才出结果，所以延迟是 4 个周期；第 1 段一空出来，下一条就能进去，所以每周期都能送进一条新的。

浮点加法在加法器里大致分成 4 段，同一时刻最多有 4 条加法分别在不同的段上：

| 段 | 做什么 |
|---|---|
| 1 | 比较两个数的指数，把指数小的那个的尾数右移对齐 |
| 2 | 两个尾数相加 |
| 3 | 规格化：把结果移成 1.xxx 的形式，调整指数 |
| 4 | 舍入 |

- **核的后端由调度器和发射端口组成**：调度器每周期从等着执行的微操作里，挑出输入已经准备好的，送到空闲的**发射端口**（port）上。
- **每个端口后面挂着几种运算电路**：以 Intel Skylake 为例（大致）：

| 端口 | 能执行什么 |
|---|---|
| 0、1 | 整数运算；浮点加、乘、FMA，各一个 FMA 单元；向量运算 |
| 5 | 整数运算；向量的重排（shuffle） |
| 6 | 整数运算；分支 |
| 2、3 | 读内存（load），各一个 |
| 4、7 | 写内存：4 送数据，7 算地址 |

- **更新的核端口更多**：比如 Golden Cove 有 12 个端口、3 个读端口。
- **每条指令走哪个端口、延迟多少可以查表**：查 [uops.info](https://uops.info/) 或 Agner Fog 的指令表。

每种运算有两个数，分开看：

- **延迟**（latency）：输入准备好以后，几个周期出结果。下一条要用这个结果，就得等这么久。
- **吞吐**（throughput）：每周期能开始几条。由“有几个单元能做”和“单元是不是流水的”决定。

| 运算（Skylake） | 延迟（周期） | 每周期能开始几条 |
|---|---|---|
| 整数加、减、位运算 | 1 | 4（端口 0、1、5、6） |
| 整数乘 `imul` | 3 | 1 |
| 浮点加、乘、FMA | 4 | 2（端口 0、1） |
| 读 L1 | 4–5 | 2（端口 2、3） |
| 整数除法 | 几十 | 远小于 1，除法单元不能完全流水 |

**用浮点加法算一遍**：

- **硬件每周期能开始 2 条加法**：但每条要 4 个周期才出结果。
- **要用满就要有 8 条加法同时在执行单元里**：4 × 2 = 8，而且这 8 条互不依赖。
- **只有一条依赖链时只用了八分之一**：每 4 个周期才能送进一条。

### 3.2 指令级并行：乱序执行把互不依赖的指令同时送进执行单元 {#ilp}

> **本质：指令级并行（ILP）是同一时刻有多少条互不依赖的指令可以执行**。

- **硬件负责找**：乱序执行在 ROB 窗口里找输入已经准备好的指令，送进空闲的执行单元。
- **依赖链决定能找到多少**：后一条要用前一条的结果就只能等，执行单元再多也并不起来。

一条指令从取进来到完成，要经过三段：

1. **前端**按程序顺序取指令、译码成微操作，每周期 4–6 条，放进 ROB 和调度器。
2. **调度器**不管程序顺序，哪条的输入准备好了、对应的端口空着，就送哪条去执行。这就是乱序执行。
3. **退休**再按程序顺序进行，所以程序看到的结果和顺序执行一样。

**ILP 不只靠流水线**：

- **ILP 是程序本身的属性**：程序里有多少条指令互不依赖。
- **硬件靠下表几样东西把它用起来**：只有流水线的话，每周期最多完成 1 条，IPC 不会超过 1。

| 机制 | 做什么 | 只靠它能到哪一步 |
|---|---|---|
| 流水线 | 一条指令的执行切成取指、译码、执行、退休几级，不同指令处在不同级，时间上重叠 | IPC 最多 1：每周期进 1 条、出 1 条 |
| 超标量（多发射） | 每一级都做宽：每周期译码 4–6 条，后面挂多个执行单元 | IPC 能超过 1，前提是按程序顺序挨着的几条正好互不依赖 |
| 乱序执行 | 调度器不按程序顺序，输入准备好的先执行；ROB 窗口往后看几百条 | 能用上离得远的独立指令，不被前面一条慢指令卡住 |
| 寄存器重命名 | 同一个架构寄存器的多次写，映射到不同的物理寄存器 | 消掉 WAR、WAW 这类名字冲突（3.4），只剩真依赖 |
| 分支预测、推测执行 | 不等分支结果，先按猜的方向接着取指令 | 窗口能跨过分支继续填；猜错就把推测的结果作废 |

**“流水线”在这里有两层意思**：

- **整个核的流水线**：取指、译码、执行、退休这几级，就是上表第一行。
- **执行单元内部的流水线**：3.1 讲的加法器内部分段，一个 FMA 单元切成 4 级，延迟 4 个周期，每周期仍能再送进一条。

**IPC 上不去，通常是下面三种原因之一**。IPC 是每周期实际完成的指令数；CPU 在 ROB 这个窗口里往后看，ROB 有 200–600 项（[CPU 速查 2.3](/zh/ref/cpu-memory/#in-flight)）。

- **依赖链**：后一条要等前一条的结果，执行单元再多也只能一条接一条。循环里最要紧的是跨迭代的链：这一轮要等上一轮的结果。3.3 到 3.6 讲这个。
- **执行单元不够**：一类指令太密，对应的端口一直满着，比如每周期要读 3 个数，读端口只有 2 个。3.9 的 ResMII 算的就是这个。
- **窗口不够大**：一次缓存缺失要几百个周期，缺失的那条退休不了，ROB 被后面的指令填满，前端就停下来。这是访存的问题，见[内存延迟与带宽](/zh/posts/low-latency-memory-latency-bandwidth/)。

**要填满执行单元，需要“延迟 × 单元数”条互不依赖的运算同时在路上**：

- **这和内存的 Little 定律是同一个式子**：要把内存带宽用满，需要“延迟 × 带宽”这么多次缺失同时在路上，靠的是 LFB（[内存延迟与带宽 1.3 节](/zh/posts/low-latency-memory-latency-bandwidth/)）。
- **挡住两者的都是依赖**：指令级并行管计算，内存级并行管访存。

**所以决定耗时的不是指令条数，而是最长的那条依赖链有多长**：

- **链上的指令只能一条接一条地等**：执行单元再多也用不上。
- **编译器能帮的有限**：它可以重排指令、展开循环，把独立的指令放到一起，但拆不掉真依赖，也不敢替你改浮点运算的顺序。

### 3.3 同样的运算，换个结合顺序 {#reassociate}

> **本质：一段计算的耗时取决于最长的那条依赖链，不取决于运算条数**。

- **下面的 `c + d` 不需要乘法的结果**：单独先算，它就能和乘法同时进行。
- **最长的链从 3 步变成 2 步**：运算条数没变，时间少了三分之一。

```cpp
// 一条链：mul -> add -> add，每一步都等上一步
double chained(double a, double b, double c, double d) {
  return ((a * b) + c) + d;
}

// c + d 不依赖乘法，可以和 a * b 同时算
double parallel(double a, double b, double c, double d) {
  double sum = c + d;
  return (a * b) + sum;
}
```

乘法和加法的延迟都按 4 个周期算：

$$\text{chained} = 4 + 4 + 4 = 12,\qquad \text{parallel} = \max(4,\,4) + 4 = 8$$

运算一样多，`parallel` 少了三分之一的时间。浮点加法换了顺序，结果可能差最后几位，所以编译器默认不替你改，要手写（3.5）。

### 3.4 迭代间依赖：写后读的真依赖才挡路 {#loop-carried}

> **本质：只有“这一轮要读上一轮写的值”（跨迭代的写后读，RAW）会让几轮没法同时做**。

- **读后写、写后写只是名字冲突**：两条语句碰巧用了同一个位置，换一个变量就消掉。
- **寄存器上的名字冲突由硬件消掉**：寄存器重命名（3.2）会自动处理。

| 依赖 | 是什么 | 例子 | 能不能消掉 |
|---|---|---|---|
| RAW（写后读，真依赖） | 后面要用前面写的值 | `a[i] = a[i-1] * 2 + b[i]`：第 i 轮等第 i-1 轮写完 | 不能，几轮没法并起来做 |
| WAR（读后写） | 先读、后写同一个位置 | `a[i] = b[i]; b[i] = c[i];` | 能，读在写之前就行 |
| WAW（写后写） | 两次写同一个位置 | 最后留下的值要对 | 能，换个临时变量 |

### 3.5 浮点求和：编译器不敢换顺序，要多个累加器 {#fp-sum}

> **本质：浮点加法换了顺序，舍入结果可能不同，所以编译器不能替你改求和顺序**。

- **单个累加器把整个循环串成一条链**：每次加法都要等上一次的结果。
- **手写几个累加器是你主动接受误差**：结果末位可能变，换来几条链同时算。

整数求和编译器可以随便换顺序，实测 `long` 求和在 `-O3` 下直接向量化（`paddq`）。`float` 不行：`(a + b) + c` 和 `a + (b + c)` 的舍入结果可能不同。一次浮点加法延迟约 3–4 个周期，开头那个循环每 4 个元素要 12–16 个周期。

```cpp
float dot_acc4(const float* v1, const float* v2, int n) {
    float s0 = 0, s1 = 0, s2 = 0, s3 = 0;
    int i = 0;
    for (; i + 3 < n; i += 4) {
        s0 += v1[i] * v2[i];
        s1 += v1[i + 1] * v2[i + 1];
        s2 += v1[i + 2] * v2[i + 2];
        s3 += v1[i + 3] * v2[i + 3];
    }
    for (; i < n; i++) s0 += v1[i] * v2[i];
    return (s0 + s1) + (s2 + s3);
}
```

四条链互不依赖，编译器把四个累加器装进一个寄存器，循环体变成一条 `mulps` + 一条 `addps`，每 4 个元素只等一次加法，约 3–4 个周期，估算快约 4 倍。累加器再多（比如 8 个，两个向量寄存器轮流加），还能把两个加法单元都填满（3.6）。

另一条路是 `-ffast-math`（或只开 `-fassociative-math`），允许编译器换顺序，实测开头的版本也变成 `addps`。但它管整个编译单元，还会改别的浮点行为（例如 4.3 的除法），交易系统里一般不全局开。

### 3.6 累加器该拆几个：K = 延迟 × 吞吐 {#accumulators}

> **本质：累加器的个数要达到“延迟 × 执行单元数”，执行单元才不会空着**。

- **一条链做完一次乘加要等一个延迟**：这段时间里，执行单元要靠别的链的乘加来填。
- **再多就没有收益**：达到这个数以后，瓶颈换成读端口或内存带宽。

```cpp
// 一个累加器：每次 += 都要等上一次，一条完全串行的链
double dot_serial(const double *a, const double *b, size_t n) {
  double acc = 0.0;
  for (size_t i = 0; i < n; ++i) acc += a[i] * b[i];
  return acc;
}

// K 个累加器：K 条互不依赖的链，只在最后合并一次
template <size_t K>
double dot_unrolled(const double *a, const double *b, size_t n) {
  double acc[K] = {};
  size_t i = 0;
  for (; i + K <= n; i += K)
    for (size_t k = 0; k < K; ++k)
      acc[k] += a[i + k] * b[i + k];
  for (; i < n; ++i) acc[0] += a[i] * b[i];   // 余下的几个
  double total = 0.0;
  for (double v : acc) total += v;
  return total;
}
```

$$K = \text{一次乘加的延迟（周期）} \times \text{每周期能发射的乘加数}$$

以乘加延迟 4 个周期、两个 FMA 单元的核为例：

| K | 每个元素平均周期 | 每周期乘加数 | 卡在哪 |
|---|---|---|---|
| 1 | 4 | 0.25 | 一条链，每 4 个周期出一个结果 |
| 4 | 1 | 1 | 填满一个 FMA 单元 |
| 8 | 0.5 | 2 | 两个 FMA 单元都满了 |
| 16 | 0.5 | 2 | 不再提升，瓶颈从依赖链变成执行单元 |

**这是只看算术的上限。** 这个点积每次乘加要读 `a[i]`、`b[i]` 两个数：每周期能读 2 个数的核，每周期最多 1 次乘加，K = 4 就碰到读的上限；每周期能读 3 个数的较新的核，最多 1.5 次。数据不在 L1 里时，内存带宽会更早卡住，这就是 roofline 模型说的算力受限还是访存受限。实际达到多少用 `perf` 测；K 拆得太多还会碰上 3.7 的寄存器溢出。

### 3.7 拆得太多：寄存器不够，就溢出到栈上 {#spill}

> **本质：每个累加器都要占一个寄存器，拆得太多就会溢出到栈上**。

- **溢出的代价是多出内存读写**：编译器把放不下的值存到栈上，每轮多读写几次内存，把拆链省下的时间又花回去。

x86-64 有 16 个通用寄存器，浮点和向量值放在 16 个 XMM/YMM 寄存器里（AVX-512 有 32 个 ZMM）。拆依赖链本来是为了少等，拆过头又加上了内存访问。

### 3.8 看不见的依赖：popcnt 的目标寄存器 {#false-dependency}

> **本质：有些指令的结果和目标寄存器原来的值无关，硬件却要等这个旧值写好才执行**。

- **循环里就多出一条看不见的链**：每轮都写同一个目标寄存器，这一轮就要等上一轮，源码里看不出来。

典型的是 Intel 好几代核（Sandy Bridge 到 Skylake 一带）上的 `popcnt`、`lzcnt`、`tzcnt`：结果和目标寄存器原来的值无关，硬件却要等它。每轮都写同一个目标寄存器的循环，就被串成了一条链：

```asm
; rax 被当成输入，这一轮要等上一轮的 popcnt 写完 rax
loop:
    popcnt rax, rbx
    ...
    jmp loop

; 先把目标寄存器清零：CPU 认得 xor 自己这个写法，知道它不依赖旧值，链就断了
loop_fixed:
    xor eax, eax
    popcnt rax, rbx
    ...
    jmp loop_fixed
```

GCC、Clang 针对这些核调优时会自动插入这条 `xor`。手写汇编或 intrinsics 时，一个不该是链的循环停顿得说不清，可以往这个方向查。

### 3.9 软件流水与 MII：吞吐上限由资源或依赖环决定 {#mii}

> **本质：一个循环每隔多少个周期能开始新的一轮，下限取下面两个约束里大的那个**。

- **执行单元够不够分（ResMII）**：每轮要用某类单元的次数，除以这类单元的个数。
- **跨迭代的依赖环要等多久（RecMII）**：环上的延迟加起来，除以环跨了几轮。

**软件流水**（software pipelining）是让相邻几轮迭代重叠执行：第 i 轮还在算，第 i+1 轮已经开始读数据。**启动间隔**（II）是相邻两轮开始之间隔几个周期，它的下界：

$$
\text{MII} = \max(\text{ResMII},\ \text{RecMII})
$$

- **ResMII（资源约束）**：每类执行单元，每轮要用几次除以有几个，取最大的。

$$
\text{ResMII} = \max_{\text{每类单元}} \left\lceil \frac{\text{每轮这类指令条数}}{\text{这类单元个数}} \right\rceil
$$

  例如每轮 3 条加法、2 条乘法，2 个加法单元、1 个乘法单元：加法 $\lceil 3/2 \rceil = 2$，乘法 $\lceil 2/1 \rceil = 2$，ResMII = 2。

- **RecMII（依赖环约束）**：跨迭代的依赖环上，延迟之和除以环跨了几轮，取最大的。

$$
\text{RecMII} = \max_{\text{每个依赖环}} \frac{\text{环上延迟之和}}{\text{环跨越的迭代数}}
$$

  例如 `a[i] = a[i-1] * 2 + b[i]`，环是“乘、加、得到 `a[i]`、下一轮拿来用”。假设乘法 2 个周期、加法 1 个周期，RecMII = 3，比 ResMII 的 2 大，瓶颈在依赖环，执行单元再多也没用。（延迟是为了算式好看假设的；x86 上 `* 2` 会编成加法或移位，`a[i-1]` 也会留在寄存器里。）

x86 上这件事主要由硬件做：乱序执行同时挂着好几轮迭代，自动重叠（3.2），编译器很少显式做软件流水。但这套算法照样能用来判断一个循环快不快：先找跨迭代的依赖链（RecMII），再数每轮占用的执行单元（ResMII）。3.5 的点积就是被 RecMII 卡住的，多个累加器把一个环拆成四个互不相干的环，RecMII 变成原来的 1/4。

## 4. 访存：让数据少搬几次

> **本质：CPU 从内存搬数据，一次搬一条 64 B 的缓存行，所以访存优化看两件事**。

- **一条行搬进来以后要把字节都用上**：4.1 的循环交换解决这个。
- **要用好几次的行，用完之前不能被挤出缓存**：被挤出去就得再从内存搬一遍，4.2 的分块和 4.3 的融合解决这个。
- **4.4 是另一类问题**：内层循环太短时，时间花在循环控制上，不在访存。

### 4.1 循环交换（interchange）：内层沿着内存连续的方向走

> **本质：内层循环每走一步地址跳多远，取决于内层走的是哪一维**。

- **沿着内存连续的方向走**：一条行里的 16 个 `float` 依次用完，硬件预取器也能提前取下一条。
- **跨着走**：每一步都落在一条新的行上，搬进来 64 B 只用了 4 B。

C++ 二维数组按行存，`m[i][j]` 和 `m[i][j+1]` 挨着，所以内层应该走 `j`。内层走 `i` 就交换内外层，[#6](/zh/posts/alignment-layout-cache-dram-geometry/) 里“按列遍历慢”就是这个原因。编译器只在能证明结果不变时才自己交换，一般要你写对。

### 4.2 循环分块（tiling）：有重复使用才有用

> **本质：分块是让同一块数据的几次使用挨在一起做完，这期间它一直留在缓存里**。

- **不分块时数据会被挤出去**：一份数据要用好几次，两次使用隔得太久，中间被别的数据挤出缓存，第二次就得再从内存搬一遍。
- **只用一次的数据分块没有用**：没有什么需要留在缓存里。

分块是把大数组切成小块，处理完一块再处理下一块。矩阵乘法里同一行、同一列要用很多次，是典型场景。转置看起来每个元素只碰一次，其实也有重复使用：

```cpp
constexpr int N = 256, T = 16;
void transpose_tiled(const float* a, float* b) {
    for (int i = 0; i < N; i += T)
        for (int j = 0; j < N; j += T)
            for (int ti = i; ti < i + T; ti++)
                for (int tj = j; tj < j + T; tj++)
                    b[tj * N + ti] = a[ti * N + tj];
}
```

**重复使用的是缓存行，不是元素**：`b` 的一条行装 16 个 `float`，要分 16 次才写满。

- **不分块**：写 `b[j*N+i]` 每步换一条行，同一条行的第 2 次写要隔 N 条别的行。N = 256 时行与行相隔 1 KiB，按组号 $(\text{地址} / 64) \bmod 64$ 只落进 L1 的 4 个组，8 路最多留 32 条，第 2 次写之前行早被挤掉，每条行要搬进来 16 次。
- **分块**：块内只碰 `b` 的 16 条行，落在 4 个组里、每组 4 条，8 路装得下。16 遍写满再离开，每条行只搬 1 次。块内的跨步写打在 L1 里的行上，和顺序写一样便宜。

**常见的多余一步**：先把 `a` 的块拷进栈上的 `tile[T][T]`，再按行写 `b`。在 CPU 上不会更快（按访存量分析，没有计时）：每条行照样各搬 1 次，多了一遍拷贝，跨步只是从写 `b` 挪到了读 `tile`。这是 GPU 的写法，GPU 上跨步写显存不能合并成一次访问。CPU 上真正的下一步是在寄存器里转置：一次读 4 行各 4 个 `float`，用 `_MM_TRANSPOSE4_PS` 交换成 4 列再整行写回，读写都从一次 4 B 变成一次 16 B。

**反例**：清零一个矩阵，每个元素只写一次，按行一路写下去就是最好的走法，实测 GCC `-O2` 整个编成一次 `memset`。硬套 16×16 分块，反而变成每行写 64 B、再跳 2 KiB。

### 4.3 融合与分裂（fusion / fission）：一遍还是几遍

> **本质：选融合还是分裂，看数据放不放得进缓存**。

- **融合把几件事放进一个循环**：对同一批数据做的几件事一起做，数据只从内存读一遍。
- **分裂把一个循环拆成几个**：每个循环体更简单、更容易向量化，但数据要读几遍。
- **数据远大于缓存时选融合**：每多读一遍，就要多从内存搬一遍。
- **数据放得进 L2 或 L3 时看向量化**：后面几遍读的是缓存，代价很小，哪种写法更好向量化就选哪种。

- **融合的代价**：循环体变大，寄存器可能不够，可能挡住向量化，占的指令缓存也多。
- **分裂的代价**：数据要扫几遍。
- **拿不准就量**：`perf stat` 对比两种写法的 icache 和 LLC 缺失。

常见的误用是把“减均值、除标准差”拆成两遍。`v[i] = (v[i] - mean) / denom` 这个单循环本来就能向量化，实测 `-O3` 编出 `subps` + `divps`，一次 4 个；拆成两遍只是多扫了一遍数组。这里真正省时间的是**把除法换成乘倒数**：除法延迟约 10–15 个周期，吞吐也慢好几倍，乘法约 4 个周期。

```cpp
void normalize(float v[], int n, float mean, float var, float eps) {
    float inv_denom = 1.0f / sqrtf(var + eps);
    for (int i = 0; i < n; i++) v[i] = (v[i] - mean) * inv_denom;
}
```

乘倒数和直接除的结果可能差最后一位，所以编译器默认不替你换；`-ffast-math` 下它会换，实测 `divps` 变成 `mulps`。

### 4.4 扁平化（collapsing）：两层循环并成一层

> **本质：内层循环只有几次迭代时，时间主要花在每一行重新进一次内层循环上，不在计算**。

- **每进一次内层循环都有固定开销**：判断够不够 4 个、处理余数、更新行首地址，真正的乘法只占一小部分。
- **能并成一层就并**：行与行在内存里首尾相接、每个元素做的事一样时，把整块当成一个长数组，只进一次循环。

`rows` 个品种，每个存 `cols` 档价格，一行接一行连续存放，全部乘一个系数。档数运行时才知道，比如 3：

```cpp
void scale_nested(float* m, int rows, int cols, float s) {
    for (int i = 0; i < rows; i++)
        for (int j = 0; j < cols; j++)
            m[i * cols + j] *= s;
}
```

`-O3` 向量化的是内层，一次乘 4 个，不够 4 个走余数处理。`cols = 3` 时每一行都是这样（GCC 13 实测，按执行顺序摘出）：

```text
    cmpl    $2, %r12d       # 不够 4 个，跳过 4 个一组的主循环
    jbe     .L24
    ...
    mulps   %xmm3, %xmm1    # 余数：先乘 2 个
    ...
    mulss   %xmm0, %xmm1    # 再乘 1 个
    ...                     # 更新行号、行首地址，进下一行
```

一行约 30 条指令、4 个条件跳转，只为 3 个数做乘法。并成一层：

```cpp
void scale_flat(float* m, int rows, int cols, float s) {
    int total = rows * cols;
    for (int k = 0; k < total; k++)
        m[k] *= s;
}
```

主循环是 `movups` / `mulps` / `movups` 加 3 条循环控制，4 个数 6 条指令，余数只在数组末尾处理一次；一组 4 个跨两行也没关系。按指令数估算，每个数从约 10 条降到约 1.5 条（没有计时）。

**不用手写、或者不能并的情况：**

- **列数是编译期常量**（写死 3）：GCC 先展开内层、再向量化外层，一轮 4 行 12 个数，等于自己扁平化了。
- **行间有空隙**（每行补齐到 64 B、`vector<vector<float>>`）：不能并。
- **做的事和行号有关**（每行乘自己的 `s[i]`）：不能直接并；用 `k / cols` 算回行号，多一次除法，不划算。

## 5. 边界：剥离、余数、哨兵

> **本质：把不规整的几轮挪到主循环外面单独处理，主循环每轮做的事完全一样**。

- **不规整的是开头和结尾几轮**：数组末尾凑不满一组的几个元素，开头地址还没对齐的几个元素。
- **主循环因此不用每轮判断**：不用检查这一轮是不是特殊情况。

### 5.1 剥离（peeling）与余数循环：把不规整的几轮单独拿出来

- **余数循环**（remainder，也叫 epilogue）：向量化的主循环一次处理 4 个（或 8 个），`n` 不是 4 的倍数时，剩下的 0–3 个单独处理。2.4 的第二个 `for` 就是；编译器向量化时会自动生成，开头那段汇编 `.L4` 之后就是一段逐个 `mulss` 的收尾。
- **剥离**：把开头或结尾的几轮单独拿出来，例如先单独做几个元素，让主循环的起始地址对齐到 16 B 或 32 B。

### 5.2 哨兵（sentinel）：在末尾放一个必然命中的值，循环里少一个判断

找第一个负数，正常每步要判断 `i < n` 和 `a[i] < 0` 两件事。末尾多留一格放一个负数，循环一定会在它那里停下，就只用判断 `a[i] < 0`：

```cpp
int find_first_negative(int* a, int n) {   // a 至少有 n + 1 格
    int saved = a[n];
    a[n] = -1;
    int i = 0;
    while (a[i] >= 0) ++i;
    a[n] = saved;
    return i;                              // == n 表示没找到
}
```

前提：数组末尾真的多出一格、可写，并且没有别的线程同时在读这个数组。

## 6. 怎么查编译器做了什么

> **本质：编译器做没做某个变换，不用猜，先看优化报告，再看循环体的汇编**。

- **报告和汇编两个都要看**：报告说“向量化了”，不等于依赖链变短了，开头的点积就是例子。

- `-fopt-info-vec`：哪些循环向量化了、用多宽的向量。
- `-fopt-info-vec-missed`：哪些没向量化、为什么（指针可能重叠、有调用、浮点不能换顺序……）。
- `-fopt-info-loop`：展开、unswitching 这类循环变换。
- `-S`：看循环体的指令。

**`-O2` 的向量化很保守。** GCC 12 起 `-O2` 也开了向量化，但只用最保守的代价模型。实测这篇里普通写法的循环（开头的点积、整数求和、`fill_10i`、归一化、`add_or_sub`）在 `-O2` 下都没有向量化；只有手写成每轮 4 条相同语句的两个点积版本，被合成了向量乘法，多累加器版连加法也成了 `addps`。这叫 SLP 向量化：把一轮里几条一样的语句并成一条向量指令，不是把几轮并起来。`-O3` 下这些循环都向量化了。热路径上的关键循环，要么用 `-O3` 编，要么对着报告确认。
