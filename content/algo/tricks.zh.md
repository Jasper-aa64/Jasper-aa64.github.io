这一页收的是一类题：**想到那个看法就 3 分钟，想不到就卡 10 分钟**。单调栈、堆、二分、滑动窗口、贪心、位运算这些标准套路见 [A1](/zh/algo/a1-complexity-binary-search-two-pointers-prefix-sums/)、[A2](/zh/algo/a2-hash-greedy-bits/)，这里不重复。代码都用题目样例跑过。

## 0. 卡住时怎么推进 {#stuck}

1. **先说暴力和复杂度**，哪怕很慢。
2. **手算两三个小例子**，边算边说看到了什么。
3. **按第 1 节的表，一行一行试**，试一个说一个：“我试试只看差值……”
4. **1 分钟没进展，就说出卡在哪**：说出来，别人才能给提示。

## 2. 例题 {#examples}

### 2.1 LC 453 最少操作使数组元素相等：等价操作

> **LC 453 的本质：其余 n−1 个加 1，等于这一个减 1，答案是每个数减最小值再求和**。

**题**：每次让其中 n−1 个元素各加 1，最少几次能让所有元素相等？

**看法**：只关心元素之间的差。其余 n−1 个都加 1，和只让这一个减 1，元素之间的差是一样的。所以问题变成：每次只能把一个数减 1，全部减到最小值要几次。

```cpp
long long minMoves(const vector<int>& a) {
    long long sum = 0; int mn = INT_MAX;
    for (int x : a) { sum += x; mn = min(mn, x); }
    return sum - (long long)mn * a.size();
}
```

**复杂度**：时间 O(n)；和可能超出 `int`，用 `long long`。

### 2.2 LC 462 最少移动使元素相等 II：中位数

> **LC 462 的本质：首尾配对，目标在中间时每一对的代价固定，所以取中位数**。

**题**：每次可以让一个元素加 1 或者减 1，最少几次能让所有元素相等？

**看法**：排序后，最小和最大的两个数配成一对：只要目标值在它们之间，这一对要移动的总步数都是“最大减最小”，与目标值具体是多少无关。再往里配第二对，依此类推。所有对都满足的位置就是中位数。

```cpp
long long minMoves2(vector<int> a) {
    nth_element(a.begin(), a.begin() + a.size() / 2, a.end());
    long long m = a[a.size() / 2], s = 0;
    for (int x : a) s += llabs(x - m);
    return s;
}
```

**复杂度**：`nth_element` 平均 O(n)，不用整个排序。

### 2.3 LC 287 寻找重复数：把数组看成链表

> **LC 287 的本质：把 i → nums[i] 看成链表，重复就有环，Floyd 找环的入口**。

**题**：n+1 个数，取值都在 1..n，只有一个数重复。要求不改数组、额外空间 O(1)。

**看法**：把 i → nums[i] 看成链表的一条边。重复的那个值有两个下标指向它，所以链表一定有环，环的入口就是重复的数。用 Floyd 快慢指针：先找到相遇点，再让一个指针从起点出发，两个指针每次各走一步，再相遇的地方就是入口。

```cpp
int findDuplicate(const vector<int>& a) {
    int s = a[0], f = a[0];
    do { s = a[s]; f = a[a[f]]; } while (s != f);
    s = a[0];
    while (s != f) { s = a[s]; f = a[f]; }
    return s;
}
```

**复杂度**：时间 O(n)，空间 O(1)，不改数组。

### 2.4 LC 41 缺失的第一个正数：下标当哈希表

> **LC 41 的本质：答案只在 1 到 n+1 之间，把值 v 换到下标 v−1，再找第一个对不上的位置**。

**题**：无序数组，找出没出现的最小正整数。要求 O(n) 时间、O(1) 额外空间。

**看法**：答案一定在 1..n+1 之间。把每个值 v（1 ≤ v ≤ n）交换到下标 v−1 上。之后从头扫，第一个满足 `a[i] != i+1` 的位置，答案就是 i+1。

```cpp
int firstMissingPositive(vector<int> a) {
    int n = a.size();
    for (int i = 0; i < n; ++i)
        while (a[i] > 0 && a[i] <= n && a[a[i] - 1] != a[i])
            swap(a[i], a[a[i] - 1]);
    for (int i = 0; i < n; ++i)
        if (a[i] != i + 1) return i + 1;
    return n + 1;
}
```

**复杂度**：每次交换都让一个值归位，总共 O(n)，空间 O(1)。

### 2.5 LC 991 坏了的计算器：倒过来想

> **LC 991 的本质：倒着推，偶数除以 2、奇数加 1，每一步的选择是确定的**。

**题**：从 x 出发，每步可以乘 2 或者减 1，最少几步能变成 y？

**看法**：正着走，每一步有两种选择，不好判断。倒着从 y 往回推，只能做“除以 2”和“加 1”：y 是偶数就除以 2，是奇数就只能加 1。一直推到 y ≤ x，剩下的差用加 1 补齐。

```cpp
int brokenCalc(int x, int y) {
    int ops = 0;
    while (y > x) { y = (y % 2) ? y + 1 : y / 2; ++ops; }
    return ops + (x - y);
}
```

**复杂度**：时间 O(log y)。

### 2.6 蚂蚁相撞：两只蚂蚁相撞掉头，等于互相穿过去

> **蚂蚁相撞的本质：相撞掉头等于互相穿过去，答案是每只走到头的时间取最大值**。

**题**：长度为 L 的杆上有若干只蚂蚁，速度相同，有的朝左有的朝右。两只蚂蚁相撞就各自掉头。问所有蚂蚁都掉下杆要多久？

**看法**：两只蚂蚁相撞后各自掉头，和互相穿过去，从外面看是一样的，只是换了个名字。所以每只蚂蚁都可以当成一直往前走、不会撞：朝右的要走 L − p，朝左的要走 p。答案是这些时间里的最大值。

### 2.7 等概率：水塘抽样、洗牌

- **水塘抽样（LC 382）：** 数据是一条流，长度事先不知道，要从中等概率地选一个。做法：第 i 个元素（从 1 开始数）以 1/i 的概率替换当前选中的。
  - **为什么等概率：** 第 i 个被选中的概率是 1/i。它之后不被替换的概率是 i/(i+1) × … × (n−1)/n = i/n。两者相乘是 1/n。
- **Fisher–Yates 洗牌（LC 384）：** i 从 n−1 往下到 1，每次在 [0, i] 里随机选一个 j，交换 a[i] 和 a[j]。每种排列的概率都是 1/n!。
  - **常见错误：** j 每次都从 [0, n−1] 里选，这样一共有 nⁿ 种结果，不能被 n! 整除，所以做不到每种排列等概率。

## 3. 常见的概率题：口头答，不写代码 {#probability}

| 题 | 答案 | 用的方法 |
|---|---|---|
| n 个人随机拿回自己的帽子，拿对的人数期望是多少？ | 1 | 期望的线性性：每个人拿对的概率是 1/n，加起来就是 1 |
| 一直抛硬币，直到连续两次正面，期望抛几次？ | 6 | 按状态列方程：设 E₀ 为还没有正面时还要抛的次数，E₁ 为刚抛出一次正面时的次数，E₀ = 1 + ½E₁ + ½E₀，E₁ = 1 + ½·0 + ½E₀，解得 E₀ = 6 |
| 掷骰子直到出现 6，期望掷几次？ | 6 | 几何分布，期望是 1/p |
| 两人轮流抛硬币，先抛出正面的赢，先手赢的概率是多少？ | 2/3 | 设先手赢的概率为 p，p = ½ + ½(1 − p) |
| 有两个孩子，已知至少一个是男孩，两个都是男孩的概率是多少？ | 1/3 | 条件概率：只剩男男、男女、女男三种等可能情况 |
| 一根木棍随机折成三段，能拼成三角形的概率是多少？ | 1/4 | 几何概率：每一段都要短于总长的一半 |

**答的顺序**：先说用的是什么方法（线性性、按状态列方程、对称性、条件概率），再列式子，最后报数。
