QD 岗位问业务，要的不是交易所协议的每个字段，而是两件事：你真的处理过这些数据，以及你知道哪些地方会让研究侧和实盘算出来不一样。下面按这个深度整理，先是 Level-2 行情本身，再是用它算的几个因子。

## 1. 三类数据

| 数据 | 记了什么 | 量级 |
|---|---|---|
| 快照 | 约每 3 秒一张：十档买卖价量、最新价、高开低收、累计成交笔数、量、金额，委买委卖总量；买一卖一前 50 笔挂单（委托队列） | 全市场一天两千多万条 |
| 逐笔委托 | 每一笔挂单（上海还有撤单） | 一天上亿条 |
| 逐笔成交 | 每一次撮合（深圳还有撤单） | 一天上亿条 |

**快照是结果，逐笔是过程**：快照只告诉你 3 秒后盘口变成什么样，谁主动成交、大单什么时候挂上又撤掉，只有逐笔看得到。Level-1 只有五档快照，没有逐笔。

## 2. 沪深两市的差别

| | 深圳 | 上海 |
|---|---|---|
| 逐笔委托记什么 | 交易所收到的每一笔新委托，原始申报数量；类型分限价、市价、本方最优 | 进入订单簿的部分：立即全部成交的不发，部分成交的只发剩余量；类型分新增（A）、删除（D） |
| 撤单在哪 | 逐笔成交里，一条标着“撤销”的成交记录，价格写 0 | 逐笔委托里，一条“删除”（D）记录 |
| 主动方 | 没有标志，比较买卖双方委托序号，大的（后到的）是主动方 | 成交带内外盘标志：B 主动买、S 主动卖、N 未知 |
| 序号 | 频道内消息记录号，委托和成交共用 | 通道内业务序号，委托和成交共用 |

一句话记：**深圳的逐笔委托记“报了什么”，上海记“挂上了什么”**。所以同一个“大单委托”因子，两市要分开写。

撤单放在哪，也是从这个区别来的。上海的逐笔委托记的是订单簿上挂单的变化：一笔单挂上去，发一条“新增”（A）；被撤下来，发一条“删除”（D）。撤单自然就在逐笔委托里。深圳的逐笔委托只记新收到的委托，撤单不是新委托，放不进去；深圳的逐笔成交记的其实是委托的执行结果，结果有两种，成交了，或者撤销了。所以深圳的一笔撤单，是逐笔成交里的一条记录，只是它的类别标成“撤销”而不是“成交”（字段叫成交类别 `ExecType`，撤销写 `4`，成交写 `F`）。撤单没有成交价，这条记录的价格写 0；数量是撤掉的量；买卖双方的委托序号只有被撤那一边不是 0，用它查回原委托，才知道撤的是哪个价位。

**所以在深圳，用逐笔成交算任何东西，第一步都是先把撤销记录滤掉**：不滤的话，撤掉的量会被当成成交量，价格 0 会把均价拉低（第 5 节）。反过来，算撤单因子时，深圳要读逐笔成交，上海要读逐笔委托，只读一路就漏掉一个市场的撤单。

## 3. 序号、回查委托、主动方

- 先后只认序号：时间戳只到毫秒，同一毫秒里一笔委托和它引发的成交常常同时间。同一通道内按序号把委托和成交合成一条流，才是交易所处理的顺序；不同通道的序号不能比。
- 丢包和重复：序号连续，收到 1001、1002、1004 说明 1003 丢了，要补或标记；断线重连后的重发按序号去重。
- 回查委托：深圳成交里的买卖双方委托序号，就是那两笔委托的消息记录号；撤单记录价格是 0，要用非 0 的那个序号查回原委托才知道撤的是哪个价位。上海成交里的买卖方订单号对的是委托的原始订单号，不是业务序号；立即全部成交的单在逐笔委托里查不到。
- 主动方：上海直接看标志；深圳比序号。集合竞价的成交没有主动方，上海标 N，深圳比序号没有意义，算主动买卖量时要把这段剔掉或单独处理。

## 4. 集合竞价

开盘集合竞价 9:15–9:25（9:20 以后不能撤单），这段只收单不成交，9:25 一次撮合，产生一批同一价格、同一时间的成交；9:30 进入连续竞价。收盘集合竞价 14:57–15:00，同样最后一次撮合。深圳的市价单和本方最优委托只在连续竞价出现，9:30 以前没有。写因子时，这几段的成交和普通连续竞价的成交性质不同，要不要算进去、怎么切 bar，得和研究侧约定。

## 5. 写因子时要和研究侧对齐的地方

| 地方 | 会怎么对不上 |
|---|---|
| 累计量相减 | 快照的量、额、笔数是开盘起的累计值。当天第一张，pandas `diff()` 给 NaN，C++ 上一张从 0 起算会得出开盘以来的全部量 |
| 快照不是每 3 秒都有 | 没变化通常不推，切 bar 时空格子用前值补还是留空要约定 |
| 价格和金额 | 价格是放大过的整数，倍数按数据商文档并用真实数据核；有的数据商成交金额是去掉角分的整数元，零股、科创板 201 股这类会少几毛，要准就用价×量 |
| 深圳撤单混在成交里 | 直接用逐笔成交算均价，价格 0、数量非 0 的撤单行会把均价拉低 |
| 时间 | 交易所时间还是本机收到时间；bar 左闭右开还是右闭；集合竞价和午休怎么切 |
| 快照和逐笔对齐 | 两者节拍和时间精度不同，按时间戳把逐笔加到快照时刻不一定等于快照的累计量；严格对齐要用逐笔重建盘口再比 |

## 6. 三个常用的 Level-2 因子

QD 面试不考因子为什么有效，那是研究员的事；考的是研究员给你一个 pandas 写的因子，你能不能把它增量地写成 C++，并且和研究侧算得一样。所以每个因子准备四件事：公式，用哪类数据，每来一条消息 C++ 要维护什么状态，和 pandas 会在哪里算得不一样。下面三个各用一类数据，正好覆盖快照、逐笔成交、逐笔委托。

### 6.1 加权盘口不均衡（OBI）：快照

买卖十档挂单量的差，离盘口越近权重越大（远端挂单撤得多，对价格影响小），$w_i$ 常取 $1/i$ 或指数递减：

$$\text{OBI}=\frac{\sum_{i=1}^{10} w_i\,(\text{bid}_i-\text{ask}_i)}{\sum_{i=1}^{10} w_i\,(\text{bid}_i+\text{ask}_i)}$$

每张快照自己就能算出来，**C++ 不需要跨消息的状态**，难点全在边界。涨停时卖盘全空，OBI 恒为 1，跌停恒为 −1，这段要不要用得和研究侧约定；两边都空（停牌、开盘前）分母为 0，pandas 除以 0 得到 inf 或 NaN 不报错，C++ 用整数算会直接崩，用浮点得到 nan 继续往下传，所以填什么值要事先说好。集合竞价期间快照上的盘口是虚拟撮合的结果，不是连续竞价的挂单，一般剔掉。快照缺失时用前值补还是留空，见第 5 节。快照只有 3 秒的节拍，要逐笔级的 OBI 得用逐笔重建盘口。

### 6.2 主动大单净流入：逐笔成交

大单的主动买入额减去主动卖出额，除以同期总成交额。**大单要按委托分，不能按单笔成交分**：一张大买单吃掉卖一到卖五，会拆成很多笔小成交，按单笔金额分档，它就被算成一堆小单。所以要先按主动方的委托把成交累加起来：上海看 B/S 标志，B 取买方订单号、S 取卖方订单号；深圳比较买卖双方的委托序号，取大的那个。

C++ 的状态因此很省。一笔主动委托到达后立即撮合，它引发的成交在序号上是连续的，所以**看到主动方的委托号变了，就可以结算上一笔**：累计金额过门槛就记大单，再加进窗口里的主动买或主动卖累加和。如果研究侧连被动方也按委托大小分档，就得再维护一张“委托号 → 累计成交额”的哈希表，委托全部成交或撤单后删掉，否则表一天下来只增不减。

和研究侧对不上的地方有三处。第一，深圳的逐笔成交里混着撤单（价格 0），要先滤掉，否则撤单量会被当成交量累加。第二，“委托多大”有两种口径：按原始委托金额，还是按实际成交金额。深圳逐笔委托有原始数量，上海立即全部成交的单在逐笔委托里查不到，只能用成交金额，两市口径要统一。第三，集合竞价的成交没有主动方，要剔掉。

### 6.3 撤单金额占比：逐笔委托和逐笔成交

一段时间内被撤掉的委托金额，除以同期新增委托金额。分子在两市的来源不同。上海的删除记录在逐笔委托里，自带价格和被删的剩余量，直接乘。深圳的撤单在逐笔成交里，价格是 0，只有数量，要用非 0 的那个委托序号查回原委托才知道撤的是哪个价位、哪一边。**所以 C++ 要维护一张“序号 → 价格、方向”的表**，委托全部成交或撤单后删掉。研究侧通常是全天数据按序号 merge 一次，C++ 只能边收边查，于是还有一个坑：程序必须从 9:15 开盘集合竞价就开始收逐笔委托，从 9:30 才开始收的话，集合竞价里挂的单在 9:30 以后被撤，就查不到原委托了。

分母两市口径也不同。上海的逐笔委托不发立即全部成交的单，部分成交的只发剩余量，所以上海的“新增委托金额”偏小，同样的撤单行为，上海算出来的占比偏高。这个因子跨市场不能直接比，要么把上海的分母用成交补回来，要么沪深分开标准化，选哪种得和研究侧约定。

## 7. 被问到时怎么讲

实习里我做的是 Level-2 接入：两家数据商的沪深快照、逐笔委托、逐笔成交转成统一结构落盘。能讲的是真实数据核出来的东西，比如价格倍数、深圳委托类别实际只有三种、上海删除记录的两种写法、上海成交金额改成价×量后核到分、序号回退其实是统计脚本太慢导致环被套圈。没做过的是在逐笔上算因子；被问到就说清楚这一点，再拿第 6 节的一个因子讲：如果让我把研究侧的这个因子写成 C++，状态怎么维护，取数和对齐会在哪些地方出问题（第 3、5 节）。
