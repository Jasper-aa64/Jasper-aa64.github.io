## 4. 一句话答案卡：不看稿说出来 {#cards}

### 4.1 行情和 SPMC {#cards-spmc}

| 问 | 答 |
|---|---|
| SPMC 是你写的吧，怎么做的 | 是我写的，在原来的代码上改的。每格带一个序号戳，生产者原地填完再盖戳，不等读者；读者自己记要第几条，看戳一比就知道能不能读。改的时候还同时关注到并解决了伪共享的问题。 |
| 为什么用共享内存 | 行情源有**频控和连接数限制**：行情网关限制一个账号能开几条连接、订阅频率多高，没法每个进程各自连一条。所以只接一次、解码一次，多个进程都能读。<br>共享内存读写不走系统调用，socket 每条都要进内核、拷贝。 |
| 为什么是广播环，不是 SPSC | 生产者不能被慢读者拖住，加读者生产者不用改；代价是慢读者会被覆盖。 |
| 什么数据能放进共享内存 | 定长、可平凡拷贝、不含指针的数据；vector、string、有虚函数的都不行，指针在别的进程里没意义。 |
| 读写进度靠什么 | 写者一个只增的序号；每个读者自己记下一条要读的号，不放共享区；读者对比序号就知道写没写到。 |
| 被套圈怎么办 | 戳比要的大，说明中间丢了；这一版直接返回这一格里那条更新的，下一条要的号跳到它后面，丢了几条就是差值。 |
| 撕裂读怎么防 | 生产者先把戳作废成 0、再写数据、最后盖新号。<br>读者复制完再读一次戳，变了就丢。 |
| 跨进程下标怎么传 | 不用传，序号就放在共享内存里，是 lock-free 的 `std::atomic`，两个进程映射同一块，看到的是同一个变量。 |
| 内存序 | 写者先写数据，再 release 存序号；读者 acquire 读序号，读到新值就一定看得到数据。x86 上这俩都是普通 mov，只拦编译器重排。 |
| 回绕 | 容量取 2 的幂，`idx & (N − 1)`；序号本身不取模。 |
| 伪共享 | 不同核写的变量在同一条缓存行，互相把对方的行打失效；`alignas` 分开，我用 128，因为相邻行预取会成对拉两行。 |
| 怎么确认是伪共享 | 先看布局（同一行、不同核写），再做只改对齐的对照实验；物理机上用 `perf c2c` 看 HITM。 |
| 预触内存页为什么要写 | 只读会映射到共享零页，第一次写才真正分配；在绑好核的线程上写，页落在本地 NUMA 节点。 |
| 中位数降 17%、P99 降 57% | 两项改动各管一头：预触消掉偶发缺页，降尾部；回调自己读时钟，每条省一次跨核读，降中位数。 |

| 问 | 答 |
|---|---|

| 回测你做了什么 | perf 找到两处：日志线程空转，改轮询间隔，CPU 降 31%；每个交易日重复分配约 17.5 GB，按实际量分配、精简结构体、跨天复用，再快约 44%。 |
| 回测系统怎么搭的（[代码](/zh/interview/backtest-framework/)） | 按交易日一天一天跑，每天 4 步：读行情文件，按股票装进各自的数组，逐条喂给因子的 `on_tick`（和实盘同一份代码），结果写成文件。框架原本就有，我做了两件事：搭验证流程（先比输出，再配对计时），再按这个流程优化装载那一段。 |
| 除了简历上的，还做过什么性能优化 | 日志库后台线程的轮询间隔填的是 1 ns、从不睡，改成 1 ms 后 CPU 降约 31%、墙钟不变，这是省资源，不是提速。另外几处量过没收：写环前预取，P99 好了但中位数慢约 7 ns；补空 bar 改成一遍线性，多轮配对的区间跨过 0，判为噪声。 |
| `Tick` 怎么瘦身的（[回测页 3.2](/zh/interview/backtest-framework/#opt-load)） | 只留装载时会写、因子会读的字段，约 850 字节减到约 370 字节；代码和交易所两个 `string` 挪进 `StockDay`，每只股票存一份，`Tick` 就成了平凡可析构的类型，arena 能整块丢。 |
| 缓存案例瓶颈 | 每条行情碰约 140 条缓存行，基本都 miss，延迟串在一起。 |
| 缓存案例怎么解决 | 成批取数让 miss 同时在路上（一批按 LFB 个数定，D = 4）、预取下一批、两个核分担 40 / 24、四路 SIMD；P50 降约 67%，每步和基线对拍。 |
| 为什么主核 40、辅核 24 | 查股票、算 move 前后依赖，拆不开，只能留在主核；辅核要等主核交接完才开始，给它少一点，它才能在主核算完自己那份之前算完。交接时把期权编号、delta、move 一起给，辅核不用再读股票记录。 |
| 哪些是 AI 做的 | 瓶颈判断、对拍标准、什么时候停是我定的；代码让 agent 写，我审、我量。现在每一步我都能从空白写出来。 |

### 4.3 C++、系统和网络 {#cards-basics}

| 问 | 答 |
|---|---|
| RAII | 资源生命周期绑在对象上，构造拿、析构还；内存、锁、fd 都适用，异常时也会释放。 |
| CRTP | 基类以派生类为模板参数，`static_cast` 调派生类实现；静态分派，收益主要是能内联。 |
| x86 内存模型 | TSO：只有“写后读不同地址”可能乱序（store buffer），所以 acquire/release 免费，seq_cst 的 store 要 `xchg` 或 `mfence`。 |
| MESI | 每条缓存行四种状态；一个核要写，先把别的核的副本作废，伪共享和 ping-pong 的代价就在这。 |
| 大页 | 一页 2 MB，同样的 TLB 覆盖更多内存，少 TLB miss；行情环、订单簿这类大块热数据适合。 |
| 缓存友好的数据布局 | 按访问模式摆数据，让一次处理碰的缓存行少、访问连续：热字段放一起，不用的删掉或挪出去；顺序访问让硬件预取跟得上；不同核写的数据放进不同的缓存行。回测里 `Tick` 约 850 → 370 字节，回放时每条读的缓存行从约 14 条降到约 6 条。 |
| 依赖链（[#9 第 3 节](/zh/posts/loop-optimization/#dependency-chains)） | 一串首尾相接的指令，后一条要用前一条的结果，链上的时间只能相加；单个累加器求和，每个元素都要等一次加法延迟（约 4 个周期）。拆成几个累加器，几条链同时跑。 |
| 指令级并行（[#9 3.2](/zh/posts/loop-optimization/#ilp)） | 一个核同一周期执行多条互不依赖的指令：同类执行单元有几个，每个内部又是流水线，乱序执行在 ROB 窗口里找输入已准备好的指令送进去。不只靠流水线，只有流水线 IPC 最多 1。用满要有“延迟 × 单元数”条独立运算同时在路上。 |
| 整数累乘为什么慢 | 乘法器能并行：`imul` 延迟 3 个周期、每周期能开始 1 条。累乘每轮要等上一轮的结果，每个元素 3 个周期，只用了三分之一；3 个累乘器就能用满。整数乘法满足结合律，编译器可以自己换顺序；浮点乘法要手写。 |
| 系统调用为什么慢 | 要切到内核态、保存恢复寄存器，还会污染缓存和 TLB；热路径上避免。 |
| 忙等还是睡眠 | 延迟敏感的读者绑核忙等（加 `pause`）；落盘这类读者睡几毫秒醒来批量读，省 CPU。 |
| 行情为什么用 UDP 组播 | 一份发给多个订阅者，没有 TCP 重传和拥塞控制带来的抖动；丢包靠序号发现，另走 TCP 补。 |
| `TCP_NODELAY` | 关掉 Nagle，小包立即发，不等攒满；下单链路都要开。 |
| 内核旁路 | 网卡数据直接到用户态（DPDK、onload / ef_vi），省掉内核协议栈和中断。 |
| lock-free 和 wait-free | lock-free：整体总有线程在前进；wait-free：每个线程都在有限步内完成。SPSC 环是 wait-free 的。 |

### 4.4 考前待过的知识点 {#review}

简历技能行里这几块 fir 没问，sec 可能补。每块先说左边那一句，追问再展开；展开的内容在右边的链接里。

| 知识点 | 一句话 | 看哪里 |
|---|---|---|
| 进程与 IPC | 进程是资源的容器（地址空间、fd 表），线程是里面的执行流；IPC 里共享内存最快，数据不经过内核拷贝，同步要自己做。 | [技能问答第 6 节](/zh/interview/cv-skills-review/#system)、[速查：IPC](/zh/ref/ipc/) |
| epoll | 要监听的 fd 存在红黑树里，就绪的 fd 由内核挂到就绪链表上，`epoll_wait` 只取这个链表，不像 `select` 每次扫全部 fd。 | [速查：epoll](/zh/ref/epoll-internals/) |
| 虚拟内存与缺页 | `malloc` 拿到的只是一段虚拟地址，第一次访问才缺页、内核才分配物理页；所以开盘前先把要用的内存写一遍。 | [速查：new 和缺页](/zh/ref/new-malloc-page-fault/) |
| 缓存友好的数据布局 | 只记一句：**一次处理碰的缓存行越少越好**。具体三招：热字段放一起、冷字段挪走；循环只读一个字段就用 SoA；不同线程写的变量分到不同的行。 | [#6 第 2 节](/zh/posts/alignment-layout-cache-dram-geometry/) |
| SIMD 向量化 | 一条指令算一排数，AVX2 一次 4 个 double；先让编译器自动向量化、看汇编确认，它做不到的热点才手写 intrinsics。追问见下面五题。 | [SIMD](/zh/posts/simd-vectorization-intrinsics/) |
| 实时调度策略与优先级 | `SCHED_FIFO` 的线程比所有普通线程先跑，同优先级之间不主动让出就一直跑；优先级反转用带优先级继承的锁解决。 | [#19 第 1、2 节](/zh/posts/scheduling-priority-inversion-kernel-tuning/) |
| 中断亲和 | 网卡中断可能落在热线程的核上把它打断；改 `/proc/irq/N/smp_affinity`，把中断挪到网卡那一侧的打杂核。 | [绑核那篇 5.5 节](/zh/posts/cpu-affinity-core-isolation-numa/#irq-affinity) |
| 基于 TSC 的延迟测量与分位数 | 前后各读一次 TSC（`rdtsc` / `rdtscp`，加栅栏防止被测代码挪出去），差值按校准出的频率换成 ns；报 P50、P99、P99.9，不报平均，平均会被少数尖刺拉高。 | [#20 TSC](/zh/posts/tsc-latency-measurement/)、[技能问答第 7 节](/zh/interview/cv-skills-review/#tools) |
| 自旋锁：TTAS、票据锁、MCS | TTAS 先用普通读等，看到空闲再 CAS，等的时候不反复抢独占权；票据锁按取号顺序给锁，公平；MCS 每个等待者在自己的节点上转，释放时只碰下一个人的那条行。 | [自旋锁](/zh/posts/spinlock-implementation/) |

**SIMD 的五个追问**

| 问 | 答 |
|---|---|
| 多个线程写相似度矩阵，怎么避免数据竞争 | 按输出切：每个线程只写自己的那几行，输入大家只读，不用锁也不用原子；`join` 之后再读结果。分界别落在同一条缓存行里，否则是伪共享（[4.1 节](/zh/posts/simd-vectorization-intrinsics/#parallel-matrix)）。 |
| AoS 改成 SoA 为什么可能更快 | 循环只用一个字段时，SoA 只搬这个字段，缓存和带宽不浪费；同一字段连续存放，一条向量 load 就装满，AoS 要先洗牌。每次用一个对象的全部字段时，SoA 反而碰的行多（[2.3 节](/zh/posts/simd-vectorization-intrinsics/#layout)）。 |
| 数据布局和 SIMD 向量化有什么关系 | 一条向量 load 只能读一段连续地址，所以要同时算的那些数必须挨着放；SoA 正好把同一个字段排成连续数组。 |
| 显式写 intrinsics，还是靠编译器自动向量化 | 先靠编译器，看报告和汇编确认它做了；它做不到的热点才手写。缓存案例里我手写了：4 个期权各走一遍同一套算式，编译器认不出这种并行，我用 `_mm256_fmadd_pd` 把 4 个并排放进一条指令（[项目页 5.6](/zh/interview/cv-projects/#case-simd)）。 |
| 编译器什么情况下才能自动向量化 | 它能证明“一排同时算”和“一个一个算”结果一样的时候：指针不重叠（`__restrict`）、`a[i]` 不依赖 `a[i - 1]`、数据连续、循环里没有调不进去的函数；浮点求和还要允许重排（`-ffast-math` 或 `omp simd reduction`）；再加 `-march` 才用得上 256 位（[2.2 节](/zh/posts/simd-vectorization-intrinsics/)）。 |
