- **场景**：研究员给的是 pandas 写的因子，实盘用 C++ 重写，两边要逐值对得上。
- **难点**：对不上的原因大多不在因子逻辑，而在两边的默认行为不同。比如 pandas 默认跳过 NaN，C++ 不会；pandas 的 `std` 默认除以 n − 1，NumPy 默认除以 n。
- **每条看两件事**：两边默认怎样，C++ 怎么写才对得上。

## 1. 数值本身：浮点加法不满足结合律

### 1.1 求和顺序

1. **为什么顺序会改结果**
   - **每次加都要舍入**：$(a+b)+c$ 和 $a+(b+c)$ 的末位可能不同。
   - **结果**：同样一列数，加的顺序一变，末几位就跟着变。

2. **两边各怎么加**

   | | 怎么加 |
   |---|---|
   | NumPy `np.sum` | 成对求和：分块两两相加，误差比顺序累加小 |
   | pandas `rolling(...).sum()` / `.mean()` | 窗口滑动时加新减旧，带误差补偿（Kahan 求和） |
   | C++ 手写循环 | 从头到尾顺序累加；滚动窗口常写成 `sum += x_new - x_old` |

   - **一次性求和**：C++ 一个循环加完，和 `np.sum` 通常差在末一两位。
   - **滚动窗口**：C++ 加新减旧没有补偿，跑一整天误差越积越大，后面的值可能差得比末位多。

3. **怎么对上**
   - **先和研究侧定好要求，是容差内一致，还是逐位一致**。
   - **容差内一致**：按相对误差比，例如 $|a-b| \le 10^{-9}\max(|a|,|b|)$。
   - **逐位一致**：C++ 按同样的顺序加。一次性求和照成对求和的分块方式写；滚动窗口也加 Kahan 补偿，或者每隔一段从头重算一次窗口和，把累积的误差清掉。

### 1.2 数学函数

- **差在哪**：`exp`、`log`、`pow` 这类函数，NumPy 在支持 AVX-512 的机器上用自己的向量化实现，和 C++ 调的 glibc 实现可能差一两个末位单位（ulp）。
- **什么时候冒出来**：量级很小，只在要求逐位一致时才看得到。
- **先查什么**：两边是不是同一台机器、同一个库。

## 2. 缺失值和窗口

### 2.1 NaN

1. **两边默认怎么处理**

   | | 默认行为 |
   |---|---|
   | pandas `sum` / `mean` | 跳过 NaN（`skipna=True`）；全是 NaN 时，`sum` 得 0，`mean` 得 NaN |
   | NumPy `np.sum` / `np.mean` | NaN 会传染，结果是 NaN；要跳过得用 `np.nansum` / `np.nanmean` |
   | C++ 算术 | 和 NumPy 一样，NaN 一路传下去 |
   | C++ `std::max(a, b)` | 结果取决于参数顺序：`std::max(NaN, 1.0)` 得 NaN，`std::max(1.0, NaN)` 得 1.0 |

2. **`std::max` 为什么看顺序**
   - **写法**：它只做一次 `a < b` 比较，成立返回 `b`，否则返回 `a`。
   - **NaN 的比较都是 false**：所以只要有 NaN，就总是返回第一个参数。
   - **要忽略 NaN**：用 `std::fmax`。

3. **怎么对上 pandas**
   - **显式跳过**：累加前判断 `std::isnan(x)`。
   - **单独计数**：记下非 NaN 的个数，平均值除以这个个数，不除以窗口长度。
   - **全是 NaN**：`sum` 给 0 还是 NaN，照 pandas 的约定来。
   - **C++ 要对上 pandas，NaN 得显式跳过**。

### 2.2 ddof：方差的分母

| | 默认分母 |
|---|---|
| pandas `std` / `var`，包括 `rolling(...).std()` | n − 1（`ddof=1`，样本标准差） |
| NumPy `np.std` / `np.var` | n（`ddof=0`） |

- **研究侧用的**：研究员在 pandas 里算的，是除以 n − 1 的那个。
- **对不上的样子**：C++ 照公式除以 n，窗口 20 时差 $\sqrt{20/19}$，约 2.6%，每个值都偏同一个比例，很好认。

### 2.3 rolling 的前几个值

1. **pandas 的规则**
   - **`min_periods=n`**：`rolling(n)` 默认窗口里凑不满 n 个**非 NaN** 的值就输出 NaN。
   - **开头**：前 n − 1 个是 NaN。
   - **中间有 NaN**：一个 NaN 落进窗口，接下来 n 个输出都是 NaN。
   - **按时间开窗**：`rolling("5min")` 这类默认 `min_periods=1`，又不一样。

2. **C++ 怎么对上**
   - **自然写法的问题**：从第一条数据就开始出值，前 n − 1 个对不上，窗口里有 NaN 时也对不上。
   - **C++ 要维护窗口里非 NaN 的个数，个数不够就输出 NaN**。

### 2.4 ewm 的 adjust

1. **两种算法**
   - **`adjust=True`（默认）**：每一步都用全部历史，按权重 $(1-\alpha)^i$ 加权，再除以权重之和：

   $$y_t=\frac{\sum_{i=0}^{t}(1-\alpha)^i\,x_{t-i}}{\sum_{i=0}^{t}(1-\alpha)^i}$$

   - **`adjust=False`**：递推，也是 C++ 最自然的写法：

   $$y_t=(1-\alpha)\,y_{t-1}+\alpha\,x_t,\qquad y_0=x_0$$

2. **差在哪**
   - **开头**：两者差得明显。
   - **往后**：权重之和趋近 $1/\alpha$，差距越来越小。
   - **ewm 对不上，典型的样子是开头差得大、后面慢慢收敛**。

3. **怎么对上**
   - **`adjust=True` 也能递推**：分子、分母各自递推（都乘 $1-\alpha$ 再加新值），每步相除。
   - **参数换算**：`span`、`halflife` 换算成 $\alpha$ 的公式照抄 pandas，例如 $\alpha = 2/(\text{span}+1)$。

## 3. 取整和整数

### 3.1 四舍五入

1. **正好在 .5 时**

   | | 结果 |
   |---|---|
   | Python `round`、`np.round`、pandas `.round` | 取偶数：`round(2.5)` 是 2，`round(3.5)` 是 4 |
   | C++ `std::round` | 远离 0：`std::round(2.5)` 是 3 |

2. **二进制表示也会改结果**
   - **例子**：`2.675` 在二进制里存的是 2.67499999…，所以 Python `round(2.675, 2)` 得 2.67。
   - **C++ 也一样**：`std::round(x * 100) / 100` 里乘 100 这一步也会舍入，结果不一定和 Python 一样。
   - **价格这类本来就是定点的数，一直用放大后的整数，不在浮点上取整**。

### 3.2 整数除法和取模

1. **两边的规则**

   | | `7 / 2` | `-7 // 2` 或 `-7 / 2` | `-7 % 2` |
   |---|---|---|---|
   | Python | 3.5（`/` 是真除法） | −4（`//` 向负无穷取整） | 1（符号跟除数） |
   | C++（两个整数） | 3（整数除法） | −3（向 0 截断） | −1（符号跟被除数） |

2. **两类错**
   - **真除法和截断**：最常见。例如成交量除以笔数求平均每笔量，C++ 两个都是整数时就丢了小数部分。
   - **负数**：算时间桶编号时会出现，例如时间减基准时刻得到负数（集合竞价在 9:30 之前）。
   - **Python 的 `/` 得小数，C++ 两个整数相除直接截断**。

### 3.3 溢出

- **Python 整数**：不会溢出。
- **NumPy、pandas 的 int64**：会溢出，而且不报错，直接回绕。
- **C++ 有符号整数**：溢出是未定义行为，编译器可能按“不会溢出”来优化。
- **最容易撞上的地方**：金额。价格放大 10000 倍存成整数，100 元是 1,000,000，再乘 100 万股就是 $10^{12}$，远超 int32 的上限（约 $2.1\times10^9$）。
- **价×量一律用 int64 或 double，并且先转类型再相乘**，否则乘法已经在 int32 里溢出了。

### 3.4 类型

- **带 NaN 的整数列**：pandas 会把它变成 float64（除非用可空整数类型 `Int64`），研究侧的“成交量”可能其实是浮点；超过 $2^{53}$ 的整数转成 float64 会丢精度。
- **float32**：只有约 7 位有效数字。C++ 为了省内存用 `float` 存价格或因子值，和 pandas 的 float64 比，第 7、8 位就开始不同。

## 4. 排名和时间

### 4.1 rank

1. **pandas 的默认**
   - **场景**：截面因子常对全市场股票排名，再归一化到 0–1。
   - **同值**：`method="average"`，取它们名次的平均，例如两只并列第 3，都记 3.5。
   - **NaN**：默认不参与排名，结果也是 NaN（`na_option="keep"`）。

2. **C++ 的自然写法**
   - **按下标给名次**：排序后按位置编号，对应 `method="first"`，同值的按出现顺序排成 3、4。
   - **同值并不少见**：停牌股收益都是 0，涨停股收益相同，名次就在这些股票上对不上。

3. **怎么对上**
   - **同值取平均名次**：排序后找出同值的一段，给它们赋平均名次。
   - **`pct=True`**：除以非 NaN 的个数，不是股票总数。

### 4.2 时间切分和前视

- **bar 的边界**：左闭右开还是左开右闭，标签用起点还是终点。pandas `resample` 按分钟切时默认左闭右开、标签在左；研究侧可能改过参数，要照着来。
- **前视**：研究侧用 `shift(1)` 保证 t 时刻只用到 t 之前的数据。C++ 是逐条收数据，只有下一条数据的时间越过边界、或者定时器到点时，才知道一根 bar 结束了。**触发时机定得不一样，同一根 bar 用到的数据就不一样**。
- **午休和集合竞价**：11:30–13:00 中间没有数据，13:00 那根 bar 跟谁连在一起；9:25 集合竞价的成交归入哪根 bar。
- **更多**：时序对齐整理在 [A 股业务知识](/zh/interview/a-share-business/) 第 7 节。

## 5. 编译选项：同一份 C++ 代码，换个选项结果就变

1. **三个选项各会不会改结果**

   | 选项 | 会不会改浮点结果 | 为什么 |
   |---|---|---|
   | `-O2` → `-O3` | 一般不会 | 只要不放开结合律，编译器不能为了向量化改变加法顺序 |
   | `-march=native` | 会 | 打开 FMA 指令后，GCC（默认的 gnu++ 方言）和 Clang 会把 `a * b + c` 合成一条乘加，中间结果不再单独舍入，末位就变了 |
   | `-ffast-math` | 会，而且可能更糟 | 放开结合律；假定没有 NaN 和无穷大；把非常小的数（次正规数）当成 0 |

2. **`-ffast-math` 为什么不能开**
   - **删掉 NaN 判断**：它假定没有 NaN，`std::isnan(x)` 可能被直接优化成 false，第 2 节所有跳过 NaN 的判断都会悄悄失效。
   - **重排求和**：放开结合律后，求和顺序会被向量化重排，第 1 节的问题又回来了。
   - **因子代码里 `-ffast-math` 不能开**。

3. **只要指令，不要 FMA**
   - **`-ffp-contract=off`**：想用 `-march=native` 的其他指令、又不想要 FMA 合成，就加上它。
   - **研究侧也一样**：NumPy 内部也有自己的向量化实现，逐位一致的前提是两边都定死实现方式，不只管 C++ 这一边。

4. **构建配置要统一**
   - **例子**：回测框架用 `-O2`、实盘用 `-O3 -march=native`，同一份因子代码就可能在末位上对不上。
   - **研究侧和实盘侧的编译选项要一致，并写进构建配置**。

## 6. 对不上时：先看差值的样子

1. **按形状定位**
   - **不要一条条看**：逐值比完，先看差值在时间上怎么分布，形状通常直接指向原因。

   | 差值的样子 | 先查什么 |
   |---|---|
   | 整列错开一格（C++ 的第 t 个等于 pandas 的第 t + 1 个） | 时间对齐、`shift`、bar 的边界和标签 |
   | 只有开头几个不对，后面都对 | `min_periods`；ewm 的 `adjust`；初始值 |
   | 开头差得大，往后越来越小 | ewm 的 `adjust=True` 和递推写法的差别 |
   | 越往后差得越大 | 滚动窗口加新减旧，浮点误差在累积 |
   | 每个值都差同一个比例 | ddof；单位或放大倍数（价格放大了 10000 倍还是 100 倍） |
   | 零星几个点差很多 | NaN 的处理；停牌、涨跌停；同值排名；整数除法截断 |
   | 全部只差末一两位 | 求和顺序、FMA、数学函数实现；按约定的容差判过 |

2. **从源头避免：两边跑同一份实现**
   - **做法**：同一份 C++ 因子代码用 pybind11 暴露给 Python 研究侧，研究和实盘跑的是同一个实现。
   - **代价**：研究员改因子要改 C++、重新编译，迭代变慢。
   - **适用**：通常只对稳定下来的因子这样做。
